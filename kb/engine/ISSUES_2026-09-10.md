## Issue #1（P0 · 文档与实现不符）：多词查询报错，"空格分隔多词为 OR"不成立

- **文档**：技术文档 §2.1：「`python kb\engine\p5_search.py 蒙特卡洛`」「空格分隔多词为 OR 关系」。
- **复现**：
  ```
  python kb\engine\p5_search.py 符号说明 三线表
  → p5_search.py: error: unrecognized arguments: 三线表
  ```
- **根因**：`p5_search.py` 的 `query` 是单个位置参数（未设 `nargs="+"`），
  第二个词被 argparse 当作未知参数。
- **建议修复**：
  ```python
  parser.add_argument("query", nargs="+")
  # 内部： query = " ".join(args.query)  → 交给现有 OR 展开逻辑
  ```
- **影响**：所有多词检索场景；且文档示例会直接教用户踩坑。

## Issue #2（P1 · 排序污染）：trigram 对英文缩写类短词大量误配，相关中文结果被挤出

- **复现**：`python kb\engine\p5_search.py 外延层 --limit 8`
  - ALIAS 展开出 `SiC / 4H-SiC / 6H-SiC`；
  - trigram 无词边界，英文 `Basic / classic` 均含子串 `sic` → 结果前 8 条中
    `GPSR_Basic.m、intrinsic_dim.m、Visio 2000（Basic Network）` 等
    **与碳化硅无关**的文件占据前排；
  - 真正相关的命中（三天极限速成 P.1146「碳化硅…外延层…红外干涉法」摘要范例）被挤出。
- **根因**：trigram 无分词/词边界概念；`SiC` 这类 3 字符 ASCII 缩写在英文语料中是高频子串。
- **建议修复**（任选或组合）：
  1. 对 **纯 ASCII 且长度 ≤5** 的查询词，改用整词匹配（word-boundary）而非 trigram 子串；
  2. 打分中加入**语言/语种一致性权重**：中文查询命中的英文代码块降权（除非查询词本身是英文）；
  3. ALIAS 缩写类条目（SiC、F-P）标注为「缩写」，用 FTS 短语匹配（`"SiC"`）或双引号短语查询。

## Issue #3（P1 · 索引失效静默）：外部修改 md 后 `chunks.line_no` 漂移，定位失准且无提示

- **复现**：
  1. 建 p1→p4 索引；
  2. 用外部脚本修改「提取后」md（本项目：超长行软换行，使行数 +30 余行）；
  3. `p5_search.py 黄金规范` → 返回 `三天极限速成…md:1818`；
  4. `read_file` 该文件 1818 行 → 实际内容是「标准五步流程」，真身漂移到 ~1850 行。
- **根因**：`files` 表未存内容指纹；外部修改（非引擎流程）改行号后索引不感知，
  文档 §5.1 的 line_no 语义失效，且**无任何过期提示**。
- **建议修复**：
  1. `files` 增加 `content_sha`（或 `nlines + size`）；p5 返回结果前抽查命中文件的
     sha/行数，不一致 → 结果头部加「⚠ 索引过期（N 个文件已变更），请重跑 p3/p4」；
  2. 或提供 `p5_search.py --rebuild-if-stale`；
  3. 文档 §5.1 补充 line_no 的失效条件（任何源 md 修改都会触发）。
