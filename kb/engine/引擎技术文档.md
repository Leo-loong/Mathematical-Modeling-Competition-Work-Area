# kb/engine 本地搜索引擎 — 技术文档

> 版本：1.3（2026-09-10）
> 1.2 变更：多词查询（#1）、ASCII 短词整词校验（#2）、索引过期检测（#3）、
> 禁删原则前移+源码标注（#4）、标签透出（#6）、修复重复组折叠路径匹配失效。
> 1.3 变更：一键增量更新 `update.py`；**全部路径动态推导（kb 整体移动零改动）**；
> 语料区含 source 根级散文件；PDF/DOC 等文献原件按"文件名级"注册（kind=doc）。
> 适用对象：使用本引擎检索的 Agent / 人工维护者。
> 一句话：对 `kb/source/` 全部语料建立"文件级 + 段落级 + 代码层"三层词法索引，查询返回路径与行号，按需精读原文。

## 1. 系统概述

### 1.1 架构

```
kb/source/（语料区，动态发现所有子目录，temp 除外）
   │
   │ p1_scan.py        只读扫描建档：清单 / 文本哈希重复组 / 质量标签
   │ p2_refine.py      规则化精修（仅"提取后"目录的 md，自动备份可回滚）
   │ p3_meta.py        元数据抽取：title / summary / keywords / 函数名
   │ p4_build_index.py SQLite FTS5(trigram) 索引构建（幂等，DROP TABLE 重建）
   │ p5_report.py      生成 kb/index/MOC.md 与 kb/index/覆盖与缺口.md
   │
   └─► data/catalog.db          检索库（唯一查询入口依赖）
        data/files.json         文件元数据（p3 产物，p4 输入）

kb/engine/p5_search.py         查询接口（CLI / 可 import）
kb/engine/t1_*.py / t2_*.py    增量更新与召回率验证脚本
```

### 1.2 设计原则（改代码前必读）

1. **源文件零改动**：唯一例外是 p2 对"提取后"目录 md 的保守精修，且先备份。
2. **不整理、不合并、不去重**：重复内容靠索引层"重复组折叠"，文件永远不动。
3. **零第三方依赖**：纯 Python 标准库（sqlite3 FTS5 trigram）。
4. **幂等可重跑**：任何一步重复执行结果一致；重建用 `DROP TABLE`，不做文件系统删除（环境有安全删除保护，见 §8）。
5. **词法检索**：BM25 + trigram + 别名词表扩展。语义改述不在召回范围内（§7.3）。
6. **禁止文件系统删除**（2026-09-10 实战踩坑后升格为原则）：引擎任何脚本禁止
   `os.remove` / `shutil.rmtree` 删除语料或索引文件——环境的 safe-delete 保护会让
   删除进回收站并可能异常中断进程。需要清理时一律 `shutil.move` 到
   `source/temp` 隔离目录，累计 3 次失败记录 `temp\待手动删除清单.txt` 交用户。

## 2. 快速开始

### 2.0 一键增量更新（最常用入口）

```powershell
python kb\engine\update.py
```

把新内容拖进 `kb\source`（**任意新文件夹或散文件均可，无需登记**）后运行即可：
自动完成 精修(可跳过)→元数据→重建索引→刷新 MOC，并输出本次新增/移除文件清单。
典型场景：① 2026 国赛文献（可下载的转 md、不可下载的由 Agent 写摘要 md）放入
新文件夹如 `source\2026文献\`；② 新一批资料解压件。变更摘要落盘 `data\update_log.txt`。

### 2.1 Agent 检索（最常用）

```powershell
# 常规查询：文件级命中 + 每文件最佳段落定位
python kb\engine\p5_search.py 蒙特卡洛

# 多词查询：空格分隔，OR 关系（每个词独立做词表扩展）
python kb\engine\p5_search.py 符号说明 三线表

# 段落级深挖：返回所有命中的 文件:行号（用于 read_file 定位精读）
python kb\engine\p5_search.py 建模方法 --deep

# 只搜代码（文件名/函数名/注释/函数体四层）
python kb\engine\p5_search.py wavelet --type code

# JSON 输出（供程序/Agent 解析）
python kb\engine\p5_search.py 小波 --json
```

**Agent 标准消费流程**：`search --json` → 取 `(path, line, section, snippet)` → `read_file(path, offset=line)` 精读上下文 → 需要溯源时按路径回查原始文件。

### 2.2 返回结果解读（文本模式）

```
扩展词: 蒙特卡洛 | Monte Carlo | MC模拟 | 随机模拟   ← 词表自动扩展，实际按这些词检索
命中: N 条
 1. [md] 标题 [低信息量]                              ← kind: md/code/text
    小节: 5.1.4.1 蒙特卡罗算法                        ← 命中块所在 md 小节
    位置: kb/source/.../xxx.md:237                   ← 文件:行号（read_file 定位用）
    摘要: ……                                         ← 命中块前 160 字符
```

- 结果行首 `[...]` 为标签（§7.4）：`文档/代码/文本`（类型）、`原始区`（未整理区，谨慎引用）、
  `低信息量`（<500 字符清单页）、`疑OCR(繁体混入)`（含简体文献罕用繁体形近字，
  OCR 错字风险高，**数字引用前必须回原件核对**）。
- 同一内容的多个副本（跨批/跨目录）只显示最优一条，其余折叠不丢。
- 纯 ASCII 且 ≤5 字符的查询词（SiC/LP/GA…）自动做整词校验，
  像 `sic ⊂ Basic/classic` 这类 trigram 子串误配会被过滤。

### 2.3 CLI 参数全表

| 参数 | 说明 | 默认 |
|---|---|---|
| `query` | 查询串；空格分隔多词为 OR 关系 | 必填 |
| `--type md\|code\|text` | 限定文件类型 | 全部 |
| `--deep` | 追加段落级深挖结果（前 60 条） | 关 |
| `--json` | JSON 输出 `{expanded_terms, hits, deep}` | 关 |
| `--limit N` | 文件级结果条数 | 20 |
| `--rebuild-if-stale` | 检测到索引过期时自动重跑 p3+p4 后重查 | 关 |
| `--no-stale-check` | 跳过索引新鲜度抽查（省几十毫秒） | 关 |

## 3. 配置项

引擎无常量文件，配置即代码中的常量，改动后重跑对应流水线（§4）生效。

| 配置 | 位置 | 说明 |
|---|---|---|
| **别名词表 `ALIAS`** | `p3_meta.py` 顶部 | **最重要配置**。`标准词: [别名...]`，检索时双向扩展。发现"搜不到但库里有"的叫法就补录，然后重跑 p3→p4→p5 |
| 额外语料根 `EXTRA_ROOTS` | `p3_meta.py` | 默认空。文献一律放 `kb/source` 内（动态发现自动纳索）；确有 source 之外的目录才在此登记（相对工作区路径） |
| 非语料目录 `NON_CORPUS` | `p3_meta.py` | source 下不入索引的目录名（当前 `temp`）；p1 同步使用 |
| 排除目录 `EXCLUDE` | `p1/p3` | 任意层级跳过（当前 `_无效内容`） |
| 可索引扩展名 `TEXT_EXTS` | `p1/p3` | md/m/M/py/c/txt/html 等；**新增类型在这里加** |
| 低信息量阈值 | `p1_scan.py`（<500 字符）、`p4` 无 | 改动影响质量标签 |
| md 切块大小 | `p4_build_index.py chunk_md(max_len=800)` | 段落块字符上限 |
| 代码切块 | `p4_build_index.py chunk_code(max_lines=120)` | 超过按 120 行分块 |
| 精修规则 R1–R4 | `p2_refine.py` | 见 §6 |
| 深挖抓取上限 | `p5_search.py`（fts 取 50000 行 → 按文件折叠取前 500） | 大库性能保险丝 |

## 4. 增量调用（核心工作流）

### 4.1 新增语料（文献/网盘补料等）—— 推荐直接用 `update.py`

```powershell
# 把新内容放进 kb\source 下任意新文件夹或散文件，然后：
python kb\engine\update.py                # 或 --skip-refine 跳过精修
```

要点：
- **目录动态发现**：`source/` 根下所有子目录与根级散文件自动纳索（`temp` 除外），
  新建 `2026文献\`、`第三批\` 等目录**不需要改任何代码**；
- **文献工作流**：可下载文献 → 下载转 md 放入 source；不可下载 → Agent 检索后写摘要
  md 放入 source。两种都是普通 md，全文可检索；PDF/DOC 原件同放会被按
  **"文件名级"注册**（kind=doc，标签`文献原件`），转 md 前也能按文件名搜到；
- **重复自动折叠**：与库内已有内容相同/高度相似的文件按文本哈希归入重复组，查询只显示一条；
- **幂等**：重复运行结果一致，不会重复入库；
- **原始区保护**：p2 只精修名字含 `提取后` 的目录；其余目录 md 保持原样。

手动分步（等价于 update.py，调试时用）：p3 → p4 → p5_report。

要点：
- **目录自动发现**：`source/` 根下所有子目录都进索引（`temp` 除外），不需要改代码登记新批次。
- **重复自动折叠**：与库内已有内容相同/高度相似的文件按文本哈希归入重复组，查询只显示一条。
- **幂等**：p3 全量重抽（3665 文件秒级）；p4 库内重建（~1 分钟）。不会重复入库。
- **原始区保护**：p2 只精修名字含 `提取后` 的目录；`第一批/第二批` 等原始目录永远只读。

### 4.2 修改词表 / 配置后

```powershell
python kb\engine\p3_meta.py && python kb\engine\p4_build_index.py && python kb\engine\p5_report.py
```

### 4.3 全量从零重建（换机器/索引损坏）

按 `p1 → p2 → p3 → p4 → p5` 顺序执行。p2 已精修过则跳过（重复执行安全，但会再次备份零改动）。

### 4.4 长任务注意

当前全量重建约 1–2 分钟，可直接前台跑。若语料增长到重建超过 ~5 分钟，按 `kb\文档批量转Markdown_踩坑与经验固化.md` 的后台规范执行：`python kb\source\temp\bg.py p4_build_index.py` + 轮询进度，禁止弹窗。

## 5. 数据结构

### 5.1 `data/catalog.db`（SQLite）

```sql
files(fid PK, path UNIQUE, area, kind,            -- kind: md|code|text|doc(doc=文献原件,仅文件名级)
      title, summary, keywords(空格分隔), nchars, dup_group,
      content_sha,                                -- 内容指纹（doc 用原始字节），过期检测用
      nlines, ocr_like)                           -- 行数；繁体形近字启发式(0/1)

chunks(cid PK, fid→files, section,                -- md: 所在小节标题
       line_no,                                   -- 1-based 行号（read_file offset 用）
       body)                                      -- md/text: 段落块；code: ≤120 行块

fts_files(title, summary, keywords)               -- FTS5, tokenize=trigram
fts_chunks(body)                                  -- FTS5, tokenize=trigram
```

- **路径口径**：`files.path` 相对 **kb 的上级目录**（如 `kb/source/xxx`），统一正斜杠；
  所有脚本路径由脚本自身位置动态推导——**kb 文件夹整体移动到正式工作目录无需改代码**。

- **trigram 特性**：≥3 字符子串精确匹配（中文按字符、ASCII 不区分大小写）；<3 字符查询自动走 `body LIKE` 兜底（§7.1）。
- **行号语义与失效条件**：`chunks.line_no` 是建索引时源文件的行号，**任何对源 md 的
  外部修改都会使其失效**（行数变化 → 漂移）。引擎每次查询对前 10 个命中文件做
  `content_sha` 抽查，发现不一致即在结果头部输出 `⚠ 索引过期` 告警；
  JSON 输出中为 `"stale": {checked, stale}` 与 `"warning"` 字段。
  消除方式：重跑 p3+p4，或查询时加 `--rebuild-if-stale`。

### 5.2 打分规则（p5_search 内部）

- 文件级 = `max(−bm25(fts_files), 标题命中×3 + 摘要命中×2 + 关键词命中×2)`，多词累加。
- 段落级 = BM25；**同一文件的全部命中块先折叠为得分最高的块**，再参与排序（防止高频词把同一批文件挤出结果）。
- 文件级无命中时回退用段落级最优块构造结果（保证 deep 场景不空手）。

### 5.3 重复组

- md：去掉页码注释与全部空白后 SHA1 相同 → 同组。
- 代码/其他文本：字节 SHA1 相同（≤2MB）→ 同组。
- 组号仅在 `files.dup_group`（p4 重建时计算），物理文件不做任何标记或移动。

### 5.4 `data/p1_inventory.csv` 字段

`relpath, area, ext, kind, size, nchars, enc, n_headings, title, hash, dup_group`——全源账本，排查"某文件在不在库里"以它为准。

## 6. 精修规则（p2，仅"提取后"目录 md）

| 规则 | 内容 | 安全性 |
|---|---|---|
| R1 | 汉字（含全角标点）之间的空格折叠 | OCR 伪影；跳过代码块与含反引号行 |
| R2 | 营销水印行（公众号/QQ群/扫码等）加 `> ` 降为引用块 | 保留原文字符 |
| R3 | `弟`+数字/中文数字+`步/天/章/节…` → `第` | 强上下文约束的形近字修正 |
| R4 | 连续 3+ 空行折叠为 1 空行 | 纯排版 |

- 修改前的原件备份在 `data/p2_backup/<原相对路径>`。
- **回滚**：把 `p2_backup` 内文件复制回源位置覆盖即可（备份只含被改过的文件）。
- OCR 件（扫描版 PDF 转的 md）仍可能有未修正的形近字，条目层面按"数字引用需回原件"处理。

## 7. 检索边界与已知限制

### 7.1 短查询

<3 字符（如"反演"）trigram 无法匹配，自动降级 `LIKE '%词%'` 全表扫（152k 块下实测 <1 秒），此时无 BM25 排序、只按文件级打分。

### 7.2 高频通用词

`function`、`figure`、`matrix` 类词全局数千块命中，目标文件可能被挤出前 500 折叠位。**这不是内容丢失**（账实核对差集为 0），换特征词（算法名/函数名/独特短语）即可。T2 实测：特征片段召回率 88.4%，未命中全部属此类；md/text 类 40/40 全中。

### 7.3 词法引擎天然查不出的内容

| 类型 | 原因 | 缓解 |
|---|---|---|
| 扫描件 PDF/CAJ/PPT/VSS 正文 | 非文本，仅文件名+目录入索引 | 补文本层版本，或人工翻原件 |
| OCR 形近字错字 | 错字按原文存储 | 按错字查询，或补 ALIAS 词表 |
| 语义改述（正文无该用词） | 词法引擎无理解能力 | 补 ALIAS 词表（主要手段） |
| 新扩展名文件 | 不在 `TEXT_EXTS` | 加扩展名后重跑 p3→p4 |

### 7.4 可信度分层（结果标签，1.2 起透出）

| 标签 | 判定 | Agent 行为指引 |
|---|---|---|
| `文档/代码/文本` | 文件类型 | 代码命中可直接复用；文档命中按小节精读 |
| `原始区` | 路径不在"提取后"目录 | 未精修内容，可能有 OCR 伪影 |
| `低信息量` | 正文 <500 字符 | 代码清单页，仅作线索 |
| `疑OCR(繁体混入)` | 含 ≥3 个简体文献罕用繁体形近字 | **数字/公式引用前必须回原件核对** |

说明：内容层面无法区分"OCR 错字"与"正当引用繁体"，故标签措辞为事实性描述
"繁体混入"而非断言 OCR；来源确凿的 OCR 件清单见 `temp\转换说明.md`。

## 8. 故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| `OSError: [safe-delete] ... trash operation` | 环境安全删除保护拦截文件删除 | 引擎代码内**禁止用 os.remove/shutil.rmtree 删语料**；p4 已改为 DROP TABLE。需删文件时移入 `temp` 隔离目录，累计 3 次失败记录 `temp\待手动删除清单.txt` 交用户 |
| 新文件搜不到 | ① 忘跑 p3/p4；② 文件在 `temp/` 下；③ 扩展名不在 TEXT_EXTS | 重跑流水线；移动目录；加扩展名 |
| 查询 0 结果但确认库里有 | 词太短走了 LIKE；或用词与原文不同 | 试 `--deep`；查 ALIAS 词表是否覆盖该叫法 |
| 结果重复感 | 重复组只按"字节/文本完全相同"归组，改写过的近似件不算重复 | 属预期；近似重复靠打分排序自然压后 |
| catalog.db 体积大（~221MB） | body 在 chunks 与 fts_chunks 各存一份 | 可接受；如需瘦身改用 FTS5 external content 表（重构点已预留） |
| 中文路径/输出乱码 | 终端编码 | 遵循 `kb\文档批量转Markdown_踩坑与经验固化.md` §2.1：脚本不用内联中文，Python 输出写 UTF-8 文件 |
