## 8.1 Trae下载安装与IDE环境配置

Trae是字节跳动推出的AI原生IDE，基于VS Code内核深度集成了AI对话面板。对数模选手来说，它解决了一个非常实际的问题：很多队员不会从零写代码，但能看懂AI写的代码，也知道哪里需要改。你的工作流从“从空白文件开始写”变为“描述需求→AI出代码→你在编辑器里跑、检查、调”。

### 8.1.1 下载与安装

安装步骤（约5分钟）：

1. 打开浏览器访问<https://www.trae.ai>，根据页面提供的版本选择macOS或Windows安装包。
2. 点击下载按钮：macOS下载`.dmg`文件，Windows下载`.exe`安装程序。
3. macOS安装：双击`.dmg`文件，将Trae图标拖入Applications文件夹即可。
4. Windows安装：双击`.exe`文件，按安装向导依次点击“下一步”，使用默认安装路径即可（一般路径为`C:\Program Files\Trae`）。
5. 首次启动：使用手机号或邮箱注册账号，模型选择保持默认（内置模型对编程任务已做专项优化）。
6. 启动后等待初始化和项目索引完成（首次约1—2分钟，后续秒开）。
7. 确认版本：启动后点击左下角齿轮图标→“关于”，确认安装的是最新稳定版本。

### 8.1.2 Solo模式与Chat模式深度对比

Trae提供了两种截然不同的AI交互模式，选错模式效率打对折。

**Chat模式（侧边栏对话）：**

- 工作方式：右侧边栏打开AI对话面板，你提问，AI回复代码片段，你手动复制粘贴到编辑器。
- 适合场景：
  1. 学习新算法——让AI讲解AHP的每一步并用代码演示；
  2. 理解报错——贴入Traceback，AI解释原因并给出修复方案；
  3. 零碎小任务——“把这个数组转成DataFrame”“这段代码加个try-except”。
- 优势：你对代码有完全的控制权，AI的每次输出你都审过了才放进项目。
- 局限：需要手动复制粘贴，每次AI不知道你项目的上下文。

**Solo模式（AI直接操作文件）：**

- 工作方式：AI获得你项目文件夹的读写权限，能创建文件、修改代码、运行脚本。你用自然语言描述目标，AI在项目文件夹里直接操作。
- 适合场景：
  1. 数据预处理全流程——“读取data.csv，做缺失值中位数填补、IQR异常值标记、Robust Scaler标准化、Frequency Encoding编码，生成清洗报告”；
  2. 批量出图——“对data.csv所有数值列画直方图、箱线图、密度图，保存到figures/目录”；
  3. 标准算法实现——AHP、TOPSIS、K-Means这些在AI训练数据里出现几万次的算法，代码生成质量极高。
- 优势：一次对话搞定整个任务，AI能读你的文件结构、理解项目上下文。
- 局限：AI改代码时可能引入你未察觉的bug，复杂多文件项目的架构决策仍需人工把关。

**实战经验——什么时候用哪个：**

- 数据预处理→Solo模式：一次性描述完整清洗需求，AI生成整套脚本。
- 算法调试→Chat模式：精确控制修改范围，逐步迭代。
- 批量出图→Solo模式：告诉AI数据文件和图表要求，一键生成。
- 学习新方法→Chat模式：边问边学，AI当随身导师。
- 复杂重构→Chat模式：每步修改都审过再执行。

**Trae环境确认清单（逐条验证，打钩通过）：**

## 8.2 Claude Code终端安装与CLI配置（MiMo API）

Claude Code是Anthropic推出的终端AI编程助手。它和Trae形成互补——Trae管图形化IDE，Claude Code管命令行。Claude Code的几个杀手特性对数模特别关键：200K上下文窗口可以一口吃进整篇论文的所有`.tex`文件做全局一致性检查；原生终端操作擅长批量文件处理（“把所有py脚本里的plt.show()改成plt.savefig()”）；深度调试时把完整报错Traceback贴进去，AI能追踪调用链定位根因。

### 8.2.1 使用方式选择——按量付费vs Token Plan

MiMo API支持两种计费方式，根据你的使用阶段选择。

| 维度 | 按量付费（Pay-as-you-go） | Token Plan（套餐订阅） |
|---|---|---|
| 计费方式 | 用多少扣多少，按token实时计费 | 固定月费/季费，套餐内含固定token额度 |
| BASE_URL | <https://api.xiaomimimo.com/anthropic> | 订阅管理页面获取专属URL（每人不同） |
| API Key格式 | `sk-`开头，如`sk-abc123...` | `tp-`开头，如`tp-xyz789...` |
| 适合阶段 | 初期测试、偶尔使用、不确定用量的新手 | 确定参赛、用量可预估、团队共用 |
| 成本估算 | 典型一次完整建模约消耗$2—8 | 月费固定，高频使用更划算 |

推荐策略：赛前一个月准备期先用按量付费，充$10测试，了解自己的实际用量。确定参赛期间每天会大量使用（预计日均$5+消耗），再切换到Token Plan。这样既不会浪费，也不会比赛时额度用完尴尬。

### 8.2.2 安装Claude Code CLI

**Step 1——安装Node.js 18+：**

1. 访问<https://nodejs.org>，下载LTS（长期支持）版本。
2. macOS：下载`.pkg`安装包，双击安装；Windows：下载`.msi`安装程序。
3. 安装完成后，新开一个终端窗口，依次验证：

```bash
node --version
npm --version
```

预期输出示例：

```text
v20.11.0
10.2.4
```

如果提示`command not found`，重启电脑后重试。

**Step 2——安装Claude Code：**

1. 在终端中执行以下命令（macOS/Linux权限不够时前面加`sudo`）：

```bash
npm install -g @anthropic-ai/claude-code
```

2. 等待下载和安装完成（约2—5分钟，取决于网络速度；如果卡住超过10分钟，按`Ctrl+C`终止后重新执行）。
3. 验证安装：

```bash
claude --version
```

预期输出类似`1.0.x`的版本号即安装成功。

**Windows用户特别注意：**不能在CMD或PowerShell中直接使用。必须先安装WSL（Windows Subsystem for Linux），具体步骤如下：

1. 以管理员身份打开PowerShell，执行：

```powershell
wsl --install
```

此命令会自动安装WSL 2和默认的Ubuntu发行版。

2. 重启电脑，按提示创建Linux用户名和密码（记好密码，之后用sudo时需要）。
3. 在WSL终端中按上述步骤安装Node.js和Claude Code（WSL终端中的路径以`~`开头，这是正常的Linux文件系统）。
4. 或者安装Git Bash（<https://git-scm.com>），在Git Bash中安装也可以。

### 8.2.3 配置凭证——关键步骤，一步都不能错

**Step 1——清理旧环境变量（防止与旧配置冲突）：**

```bash
unset ANTHROPIC_AUTH_TOKEN
unset ANTHROPIC_BASE_URL
```

如果之前配过其他Claude API的环境变量，这步不清会导致新配置不生效。

**Step 2——创建配置文件：**

1. 确认目录存在：

```bash
mkdir -p ~/.claude
```

2. 创建或编辑`~/.claude/settings.json`（用任意文本编辑器），写入以下内容：

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.xiaomimimo.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的APIKey",
    "ANTHROPIC_MODEL": "mimo-v2.5-pro",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "mimo-v2.5-pro",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "mimo-v2.5-pro",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "mimo-v2.5-pro"
  }
}
```

注意：`ANTHROPIC_AUTH_TOKEN`中必须替换为你自己的真实API Key。

字段说明：

- `ANTHROPIC_BASE_URL`：按量付费用户填上面这个固定地址；Token Plan用户填订阅管理页面给你的专属地址。
- `ANTHROPIC_AUTH_TOKEN`：按量付费填`sk-xxxxx`格式的Key；Token Plan换成`tp-xxxxx`格式。
- `ANTHROPIC_MODEL`：默认模型，推荐`mimo-v2.5-pro`。需要超长上下文（1M tokens）时加`[1m]`后缀。
- 三个`DEFAULT`字段：统一填相同模型名，避免不同场景下自动切换到你未付费的模型。

**Step 3——完成初始化：**

```bash
echo '{"hasCompletedOnboarding": true}' > ~/.claude.json
```

此命令创建`~/.claude.json`文件，内容只有一行，标记Onboarding已完成。

**Step 4——验证配置（新开终端窗口！）：**

```bash
cd /你的数模项目目录
claude
```

首次启动选择“Trust This Folder”。进入Claude Code后，依次输入以下命令验证：

```text
/status
```

确认输出的模型名是`mimo-v2.5-pro`、API端点正确。

```text
/context
```

确认上下文窗口大小显示为200K或更大。随便问一个问题（如“今天是几号”）确认AI正常响应。

**认证失败排查（按以下顺序逐一检查）：**

1. BASE_URL是否匹配你的付费方式？（按量付费和Token Plan的URL不同！）
2. API Key是否完整复制？（打开MiMo后台→API Keys→重新复制→粘贴，确保无首尾空格或换行。）
3. 环境变量冲突——执行以下命令检查：

```bash
env | grep ANTHROPIC
```

看有没有旧的环境变量覆盖了配置文件中的值。

4. 配置文件JSON格式是否正确？用以下命令验证语法：

```bash
python -m json.tool ~/.claude/settings.json
```

如果输出格式化后的JSON则语法正确；如果报错则说明某处缺少逗号或引号。

5. 确认开了新的终端窗口——旧终端不会自动加载新配置。

### 8.2.4 Claude Code数模核心用法

配置完成后，以下是你日常最高频使用的操作：

- `/edit`——让AI直接修改当前打开的文件。比复制粘贴快一个数量级。
- 贴完整报错Traceback——AI能追踪调用链，定位根因而非表面症状。
- `cd`到项目根目录启动——AI自动扫描全项目结构，理解文件间依赖关系。
- LaTeX论文全局修改——200K上下文一口读进所有`.tex`文件，“把全文中`\alpha`统一改成`\beta`”“把所有figure环境加上`[H]`定位”。
- Git辅助——让AI写commit message、分析diff变更、解决合并冲突。
- 多文件批量重构——“把项目里所有py文件中的pd.read_csv都加上encoding='utf-8-sig'参数”。

**高级技巧：**

- 项目规则文件：在项目根目录放一个`CLAUDE.md`，写入项目规范（如“所有Python代码使用4空格缩进”“matplotlib图不使用seaborn”“数据文件编码统一utf-8-sig”），AI每次对话自动读取遵守。
- 会话管理：输入`/resume`恢复上次对话；长任务可以分阶段，每阶段用`/compact`压缩上下文释放token。
- 模型切换：对话中用`/model`查看和切换可用模型。数学推导用pro模型，简单文本处理用fast模型降低成本。

## 8.3 DeepSeek API申请与配置

DeepSeek是国产模型中的可选方案之一，对数模竞赛有三个突出优势：价格较低——具体单价和与其他模型的相对比例属于版本或日期敏感信息，使用前请以官方当前价格页为准；DeepSeek-R1的思维链模式可用于数学推导和公式验证；中文理解自然，适合论文润色和中文表达打磨。

### 8.3.1 API申请

申请步骤（约10分钟）：

1. 浏览器打开<https://platform.deepseek.com>。
2. 使用手机号或邮箱注册账号，完成实名验证（按要求上传身份证信息）。
3. 登录后进入控制台→左侧菜单“API Keys”→点击“创建新的API Key”。
4. 给Key起个名字（如“数模比赛”），点击创建。
5. Key只显示一次！立即复制保存到安全位置（密码管理器或加密笔记）。
6. 进入“概览”页面→点击“充值”，先充少量余额测试。具体充值金额、价格和可调用额度属于版本或日期敏感信息，使用前请以官方当前价格页和计费说明为准。
7. 查看“用量统计”页面，了解你的消耗速率——建立对费用的感知。用量统计口径和页面功能可能随版本变化，属于版本或日期敏感信息，应以官方当前页面为准。

### 8.3.2 Python调用

**基础调用模板：**

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的DeepSeek-API-Key",
    base_url="https://api.deepseek.com"
)

response = client.chat.completions.create(
    model="deepseek-chat",
    # model="deepseek-reasoner", # 数学推导时切换
    temperature=0.1,
    # 数模任务设低值保证输出一致
    messages=[
        {"role": "system", "content": "你是数学建模竞赛Python专家，代码加中文注释。"},
        {"role": "user", "content": "用熵权法计算三个指标的客观权重。"}
    ]
)

print(response.choices[0].message.content)
# 查看token消耗
print(f"用了{response.usage.total_tokens} tokens")
```

**数模场景的模型选择策略：**

- 日常代码生成/数据处理：用`deepseek-chat`，速度快、成本低。
- 数学公式推导/验证：切换到`deepseek-reasoner`，它会展示完整的思维链推导过程。把你的手算结果和AI的结果对照——不一致的地方就是潜在的推导错误。

论文中文润色：用`deepseek-chat`，中文语感最好。Prompt示例：“逐句检查以下论文段落：术语是否统一、逻辑是否连贯、有无空洞结论”。

批量文本处理：大量数据标注、多段内容改写等任务，利用低价优势批量调用。

**成本控制技巧：**

- `temperature`设0.1—0.3减少重复生成（数模场景不需要创意性）。
- 用`max_tokens`参数限制回复长度，避免AI“废话”浪费token。
- 批量任务先拿小样本测试Prompt，确认输出质量后再全量跑。
- 日常留意usage信息，建立自己的成本感知——每次调用后打印`response.usage.total_tokens`。

## 8.4 Prompt工程——四要素与五法则

同样是AI工具，有人两句Prompt就得到可运行的代码，有人来回十几轮还在调格式。差距不在于“会不会说话”，而在于是否理解AI的输入机制。AI不是读心术——你给的上下文越精准，输出质量越高。这四条要素和五条法则是从数百次实战中提炼的Prompt方法论，三个工具（Trae、Claude Code、DeepSeek）通用。

### 8.4.1 Prompt四要素——好Prompt的骨架

四条要素，缺一条效果打对折。

**要素一：角色（Role）——激活AI的专家模式。**

- 差：“帮我分析数据”。
- 好：“你是数学建模竞赛的数据科学家，擅长Python数据处理和统计建模。”
- 原理：指定角色后，AI会调用该领域的知识框架、术语体系和最佳实践。没有角色时，AI的回复往往泛泛而谈。

**要素二：任务（Task）——越具体，输出越精准。**

- 差：“帮我做数据清洗”。
- 好：“用IQR法（1.5倍标准）检测data.csv中所有数值型列的异常值，输出每列的异常值数量和比例，将异常值标记为NaN但不删除。”
- 原理：模糊的任务描述给AI留下了巨大的“自由发挥空间”——它可能用了你没想到的方法、输出了你不需要的格式、跳过了你以为“理所当然”的步骤。

**要素三：格式（Format）——明确输出长什么样。**

- 差：“把结果输出出来”。
- 好：“用Python代码实现上述步骤，代码加中文注释。运行后打印：(1)每列异常值数量；(2)异常值占比；(3)处理前后的箱线图对比（figsize=(12,6)，保存为outlier_report.png）。”
- 原理：没有格式约束时，AI可能输出纯文字描述、伪代码或不完整的代码片段——这些你都需要二次加工。

**要素四：思维链（Chain-of-Thought）——让AI展示推理过程。**

- 差：“判断该用哪种标准化方法”。
- 好：“先判断数据分布——如果有极端值，用Robust Scaler；如果近似正态，用Z-Score；如果只需要0—1范围，用Min-Max。基于data.csv的分布特征给出推荐并解释原因。”
- 原理：要求AI“先判断→再选择→最后解释”，不仅提升答案质量，你还能看到它的决策逻辑——如果逻辑有漏洞，你可以精准修正。而不要求思维链时，AI可能跳过推理直接给结论，正确率大幅下降。

### 8.4.2 Prompt五法则——让AI输出“一次过”

实战检验的五条黄金法则：

**法则一：越具体越好——“一次给够信息”。**

模糊Prompt导致AI来回追问5—6轮才搞清楚你要什么——每轮都消耗token和时间。

精细Prompt包含：数据格式（CSV？行列数？列名？）、处理方法（用什么算法？参数？）、输出要求（格式？文件名？）、验收标准（期望的数值范围？）。

练习：对比你最近一次失败的AI对话，找出Prompt中缺少了哪条要素。

**法则二：要求解释——“你为什么这样选”。**

在Prompt末尾加一句：“对每个关键决策，解释为什么这样选而不是其他选项。”

这迫使AI暴露它的推理逻辑——如果它说“因为数据有极端值所以选了中位数”，你可以追问“极端值有多少？是什么原因造成的？”发现AI可能没考虑到的因素。

典型场景：模型选择时——“为什么选ARIMA而不是ETS？请从数据特征角度分析”——AI的回答常常暴露出它其实没真正理解你的数据。

**法则三：要求复核——“用另一种方法验证”。**

AI不会主动承认错误，但当被明确要求复查时，它在约15—20%的情况下能发现自己的错误。

在关键计算后加：“请用另一种方法验证以上结果。如果两次结果不一致，分析差异原因。”

数模特定用法：熵权法算出权重后，让AI用CRITIC法再算一遍对比；TOPSIS排序后，用灰色关联度法验证排名一致性。

**法则四：数据别省略——“AI看不到你的附件”。**

这是新手最容易犯的错误。你电脑上的data.csv对AI来说是不存在的。

至少贴数据的前5行+列名，让AI理解数据结构。样本量大的话贴描述性统计（均值、标准差、min/max）。

格式模板：“数据共500行×8列。列名：age, income, education, city, ……（此处为示意省略）。前5行：[粘贴数据]。age范围18—75，income范围2000—50000。”

**法则五：一次只做一件事——“拆分复杂任务”。**

不要在一个Prompt里写“数据清洗+特征工程+建模+画图+写论文”。拆成独立对话：对话1=数据理解与清洗方案→对话2=特征工程→对话3=建模→……

好处：每个对话的上下文聚焦，AI不会混淆不同阶段的细节；出错时容易定位是哪一步的问题。

例外：Claude Code的200K上下文可以处理较长任务，但仍建议把“代码实现”和“论文写作”分开。

### 8.4.3 实战对比——同一个任务，不同Prompt的差距

**差Prompt（费3轮以上才能用）：**

> “帮我做TOPSIS分析。”

AI可能的回复：“请提供数据和权重。”（第1轮浪费）你贴数据。AI回复——可能用了你没要求的标准化方法、没给中间结果、排名方向搞反了。你要再追问“中间结果呢？”“排序对吗？”——来来回回至少3轮。

**好Prompt（一次搞定）：**

> 你是数学建模竞赛Python分析师。对以下5城市×5指标标准化矩阵$Z$（已经过向量归一化，全部为效益型指标）做TOPSIS综合评价。
>
> 权重向量$w=[0.160,0.398,0.242,0.079,0.122]$（已通过AHP+熵权法组合确定）。
>
> 要求按顺序输出：(1)加权标准化矩阵$V=Z\times\operatorname{diag}(w)$，展示为DataFrame；(2)确定正理想解$V^+$和负理想解$V^-$（每列取max和min）；(3)计算每个城市到正负理想解的欧氏距离$D^+$和$D^-$；(4)计算相对贴近度$C_i=D_i^-/(D_i^++D_i^-)$，按$C$值降序排列；(5)每步输出完整中间结果，方便我核对；(6)代码加中文注释，变量名用英文（方便后续修改）。
>
> 数据矩阵$Z$（5行×5列，行=城市A/B/C/D/E，列=经济/环境/交通/住宿/景观）：`[[0.45, 0.52, 0.38, 0.41, 0.48], [0.51, 0.48, 0.42, 0.45, 0.52], [0.38, 0.55, 0.35, 0.39, 0.44], [0.42, 0.50, 0.40, 0.43, 0.47], [0.47, 0.46, 0.44, 0.48, 0.41]]`。

为什么这个Prompt一次就能得到可用的输出：角色明确→AI进入专家模式；任务完整→TOPSIS的四个步骤全部覆盖；数据完整→矩阵直接可运行；格式精确→每步输出什么说清楚了；有验证设计→“方便我核对”暗示AI输出要完整可追溯。

## 8.5 三大工具适用场景对比与协同方案

工具不是越多越好——三款都装、三款都用、但要在对的时间用对的工具。

### 8.5.1 三工具协同工作流——72小时完整时间线

以下是我带过几十支队伍后总结的最优工具轮换方案。记住原则：每个阶段锁定一个主力工具，不要频繁切换。

**第0—8小时（数据预处理期）——主力：Trae**

打开Trae的Solo模式，把附件数据拖入项目文件夹。用一段完整Prompt描述所有数据清洗需求——缺失值填补策略、异常值检测方法、标准化方案、编码方式、输出的清洗报告格式。Trae一次性生成整套清洗脚本。

你在旁边做的事：不是发呆。是审核AI的每一步输出——缺失值为什么选了中位数而不是KNN？异常值标记了哪些？标准化用了哪种方法？每一步都要能说出理由。因为后面建模出问题时，你首先要排除“是不是数据清洗错了”。

遇到报错就在Chat模式里贴错误信息让AI修。这8小时内，Claude Code和DeepSeek基本不用动。

**第8—24小时（建模攻坚期）——主力：Claude Code**

建模阶段，项目文件已经很多——数据文件、清洗脚本、初步分析结果、各问题的求解脚本。需要跨文件批量操作。切换到Claude Code：在终端里`cd`到项目目录，启动后AI自动扫描全项目结构。

典型操作：“把问题一的KNN分类改成SVM，同步更新plot_results.py里的模型名称和图例，然后把新结果和旧结果做个对比表”——这种跨3—4个文件的批量修改，Claude Code一句话搞定。Trae的Solo模式也能改多文件，但Claude Code的200K上下文在处理这种“全局一致性修改”时明显更可靠——它不会改了A文件忘了B文件。

**第24—48小时（论文构建期）——三工具轮换**

各问题求解基本完成后，进入论文写作阶段。这是三工具协同最密集的时期：

- Claude Code：LaTeX论文主体构建。把论文模板（`CLAUDE.md`中的规范）贴给它，让它逐章节生成tex文件。200K上下文可以一口读进所有tex文件做全局检查——引用编号是否连续、符号是否统一、图表编号是否按出现顺序。
- Trae：论文插图。根据求解结果的数据快速出图——折线图、热力图、柱状图。Solo模式：“从result.csv读取数据，画三张图：城市得分柱状图、指标权重饼图、贴近度排序表，全中文，dpi=300，保存到论文的figures目录”。
- DeepSeek API：批量校对。把论文段落逐段发给DeepSeek，检查术语一致性、数据准确性、逻辑连贯性。利用低价优势做全量检查。

**第48—72小时（最终打磨期）——主力：DeepSeek**

论文终稿打磨。DeepSeek的中文处理能力在三个工具中是最强的——它能识别出“本文采用”和“本文使用了”前后的主语不一致；能发现“如图3所示”但图的编号实际是图4；能标注出“效果较好”“结果合理”这类缺少数字支撑的空洞结论。

这时候用DeepSeek不是因为便宜——是因为它中文语感最好。Claude Code在英文环境下训练数据更多，中文表达的微妙差异容易被忽略。而数模论文是中文写作，最后一遍审校交给中文最强的工具，这是工具选择的底层逻辑——不是看哪个工具功能多，是看哪个工具在这个具体任务上最强。

**核心原则：**不要频繁切换工具。每次切换的代价不是工具启动的几秒钟，而是每次切换都要重新交代上下文和数据背景——这才是最大的时间黑洞。每个阶段锁定一个主力工具，另一个工具只在特定需求时打开，用完立刻切回。

### 8.5.2 团队分工方案

**三人分工+工具分配：**

**编程手（负责代码+图表）：**

- 主力工具：Trae（Solo模式做数据预处理+批量出图，Chat模式做算法调试）。
- 辅助工具：Claude Code（复杂多文件重构、深度调试时使用）。
- 关键能力：不是写代码速度，是审核AI代码质量的能力——能一眼看出AI生成的代码哪里可能出bug。

**建模手（负责算法+方法论）：**

- 主力工具：DeepSeek API（方法速查、公式验证、数学推导检查）+ Claude Code（文献分析、模型对比）。
- 辅助工具：Trae Chat模式（理解报错、快速测试小段算法代码）。
- 关键能力：不是背公式的数量，是模型选择的判断力——看到问题类型就知道该用什么方法，并能为选择提供充分理由。

**写作手（负责论文+排版）：**

- 主力工具：Trae Chat模式（逐段写作、润色）+ TeX Studio（编译预览）。
- 辅助工具：Claude Code（LaTeX全局一致性修改）+ DeepSeek API（中文润色+校对）。
- 关键能力：不是LaTeX命令的记忆量，是判断AI输出质量的能力——能识别逻辑跳跃、术语混用、缺少数据支撑的空洞结论。

## 8.6 TeX Live/MacTeX与TeX Studio安装配置

数模论文为什么强烈推荐LaTeX？Word有三个硬伤在竞赛场景下会放大：公式多的时候排版丑陋且难以维护（修改一个公式可能导致整页排版崩掉）、图表编号和交叉引用得手动管理（加一张图后后面几十个编号全要手动改）、多人协作时格式极容易乱（不同的Word版本、不同的默认样式）。LaTeX的公式即代码、引用自动编号、内容和格式完全分离——历年国赛优秀论文几乎100%使用LaTeX。

### 8.6.1 安装TeX发行版

安装步骤（注意：完整安装需要30—60分钟，占硬盘4—8GB）。

**关键决策：**选完整安装（Full），不要选Basic。Basic版只包含核心包，比赛时发现缺宏包（如`algorithm2e`、`mdframed`、`tikz`等常用包），临时安装可能因网络问题耗掉你半小时——在72小时比赛里这是致命的。

**macOS：安装MacTeX**

1. 浏览器打开<https://tug.org/mactex/>。
2. 下载MacTeX.pkg（约4.3GB，推荐用下载工具防中断；网络慢可用清华镜像：<https://mirrors.tuna.tsinghua.edu.cn/CTAN/systems/mac/mactex/>）。
3. 双击`.pkg`文件→按安装向导→输入管理员密码→等待10—20分钟（安装进度条走完前不要关闭或休眠电脑）。
4. 安装完成后新开终端窗口，验证：

```bash
xelatex --version
```

预期输出示例：`XeTeX 3.141592653-2.6-0.999995 (TeX Live 2025)`。

5. macOS上MacTeX自动配置PATH，无需额外操作。
6. 如果`xelatex`命令找不到：重启电脑，或在`~/.zshrc`中添加以下行后执行`source ~/.zshrc`：

```bash
export PATH="/Library/TeX/texbin:$PATH"
```

**Windows：安装TeX Live**

1. 浏览器打开<https://tug.org/texlive/>。
2. 推荐使用清华TUNA镜像站（<https://mirrors.tuna.tsinghua.edu.cn/CTAN/systems/texlive/Images/>）下载ISO镜像，速度远超官方源。
3. 右键ISO文件→“装载”（Windows 10/11自带虚拟光驱）。
4. 右键`install-tl-windows.bat`→“以管理员身份运行”。
5. 安装向导中确认：安装方案选“Full”（完整）；安装路径不要含中文或空格（默认`C:\texlive\2025`即可）。
6. 点击安装，等待20—40分钟（取决于硬盘速度；确保电脑不会自动休眠）。
7. 装完打开CMD（命令提示符），验证：

```bash
xelatex --version
```

输出版本信息即成功。

8. 如果命令找不到：将`C:\texlive\2025\bin\windows`添加到系统PATH（右键“此电脑”→属性→高级系统设置→环境变量→系统变量Path→新建→粘贴路径→确定）。

网络慢的备选方案：用TeX Live的net-installer（在线安装器）较小但需要全程联网下载，不稳定。更推荐在网速好的地方提前下载完整ISO，U盘拷贝到比赛电脑安装。

### 8.6.2 TeX Studio安装与配置

TeX Live/MacTeX提供命令行编译能力，TeX Studio则提供图形化编辑体验——代码高亮、一键编译（F5）、内置PDF预览、语法自动补全。

**TeX Studio配置（装完必做，5分钟）：**

1. 访问<https://www.texstudio.org>下载对应系统版本，双击安装。
2. 打开TeX Studio→顶部菜单Options→Configure TeX Studio。
3. Build（构建）设置：
   - Default Compiler（默认编译器）：下拉选择XeLaTeX（处理中文必须用XeLaTeX，不能用PDFLaTeX）。
   - Default PDF Viewer：选“Internal PDF Viewer (Embedded)”——内置PDF预览最方便。
4. Editor（编辑器）设置：
   - 确认Encoding（编码）为UTF-8。
   - 勾选“Show Line Numbers”（显示行号）——报错时定位必备。
5. 点击OK保存设置，关闭TeX Studio重新打开使配置生效。

### 8.6.3 中文支持与字体配置

**中文配置要点：**

推荐方案——使用ctex宏包（最简单）：

```latex
\documentclass[UTF8]{ctexart}
```

ctex宏包自动检测操作系统并选择合适的中文字体，99%的情况下不需要手动配置。

查看系统可用中文字体：

```bash
fc-list :lang=zh
```

常见输出：

- macOS：Songti SC（宋体）、Heiti SC（黑体）、STKaiti（楷体）、PingFang SC（苹方）。
- Windows：SimSun（宋体）、SimHei（黑体）、KaiTi（楷体）、FangSong（仿宋）、Microsoft YaHei（微软雅黑）。

中文字体缺失的常见错误和解决：

- 报错“Font ... not found”→用`fc-list`确认系统中文字体名，在`\setCJKmainfont{}`中使用完整字体名。
- PDF中文显示为方框→编译器选错了，必须用XeLaTeX，不能用PDFLaTeX或LaTeX。
- ctex报“Unknown option”→ctex宏包版本过旧，执行以下命令更新：

```bash
tlmgr update ctex
```

网络问题无法在线安装的应急方案：提前在网速好的环境把所有可能用到的宏包装好。比赛时如果缺包无法联网下载，可以手动下载`.sty`文件放到tex文件同目录下（LaTeX会优先搜索当前目录）。

## 8.7 TeX Studio+AI工具协同写作

标准工作流只有三步循环：AI生成LaTeX源码→TeX Studio编译预览→根据效果反馈AI调整→再编译。

你不需要记住所有LaTeX命令——AI就是你的LaTeX字典。你需要的是三项核心能力：

1. 能看懂AI生成的代码结构——`\section`、`\begin{table}`、`\cite`这些基本结构你要认识，否则连“这段代码是管什么的”都判断不了；
2. 能把编译报错准确描述给AI——不是贴一个“编译失败了”，而是把完整log信息或至少第一个Error的那几行贴过去；
3. 能判断AI的输出是否合理——公式对不对、表格数据是不是你算出来的那些数字、引用编号有没有错位。

**完整论文写作流水线（从零到终稿）：**

1. 选模板→搭框架：选定LaTeX模板，按照论文结构创建分章节tex文件（0.摘要.tex、1.引言.tex、...）。
2. AI辅助生成初稿：将每个章节的写作要求（参照`CLAUDE.md`中的论文规范）逐章提供给AI，生成tex初稿。
3. 编译检查：F5编译，查看PDF预览，标记所有问题——格式不对、内容缺失、排版溢出、引用??。
4. AI修改：将问题逐一反馈给AI修改tex源码，修改后立即编译验证。
5. 图表插入：将Trae生成的论文插图放入`figures`目录，在tex中添加`\includegraphics`引用。
6. 交叉引用检查：全局搜索`\ref`和`\cite`，确认每个引用都有对应的标签和文献。
7. 格式统一：字体、字号、行距、图表宽度、参考文献格式——用AI做最后一轮全文档一致性检查。
8. 最终编译：删除所有辅助文件（`.aux`、`.toc`、`.out`等）→连续编译两遍XeLaTeX→确认无Error→检查PDF完整性（能翻到最后一页即正常）。

结论这一章覆盖了从工具安装、配置、到协同使用的完整链条。回顾一下核心要点：Trae管IDE编码和图表（适合单文件开发和可视化），Claude Code管命令行批量和LaTeX（适合多文件重构和论文构建），DeepSeek管低成本推理和中文润色（数学验证和论文校对的最佳选择）。三人团队按编程手（Trae+Claude Code）、建模手（DeepSeek+Claude Code）、写作手（Trae+TeX Studio+DeepSeek）分工。Prompt四要素（角色、任务、格式、思维链）和五法则（具体、解释、复核、数据、拆分）是所有AI工具通用的底层方法——掌握了它们，换任何AI工具都能快速上手。

最后再强调一遍：赛前一个月搞定所有安装和配置。比赛72小时里，工具应该是你身体的一部分——不需要临时研究怎么使用，只需要专注于要做什么。
