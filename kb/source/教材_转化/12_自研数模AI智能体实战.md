## 12.1 什么是 Skill——Claude Code 的定制化 AI 能力
### 12.1.1 从“每次重新交代”到“一次配置永久生效”
如果你用Claude Code、ChatGPT 或其他通用 AI 做过一次数学建模题，你一定能体会这种痛苦：每次打开
新对话，你都要从零开始交代——“请用matplotlib 不要用seaborn”“表格请用三线表”“正文不要分点符号”“图
的标题用caption 不要用set_title”“参考文献用GB/T 7714 格式”——光是把这些规则说清楚，就要花掉你半个多小时。而且AI 还经常“忘记”：对话长了之后，前面的规则被上下文窗口挤出，后面的输出又开始违规。
这就像你每天上班都要重新培训一个新员工——而且这个员工还每8 小时失忆一次。
Skill（技能）就是解决这个问题的。
在Claude Code 中，Skill 是一个包含规则文件和模板资源的文件夹。当你在这个文件夹中启动Claude Code
时，AI 会自动读取文件夹根目录下的CLAUDE.md 文件，将其中的所有规则加载为“永久上下文”——在整个对
话过程中，这些规则始终有效，不会被上下文窗口挤出，不需要你反复提醒。
> **Skill 的技术原理——三个关键概念：**
1. CLAUDE.md——规则的“宪法”。这是一个Markdown 格式的文本文件，放在项目根目录。Claude Code
启动时自动读取，将其内容作为最高优先级的系统指令。文件中可以包含：执行流程、格式规范、代
码标准、异常预案——任何你希望AI 在本次项目中始终遵守的规则。文件越长，AI 越“懂你”，但也
会消耗更多上下文。本 Skill 的CLAUDE.md 约 700 行，是经过大量实战测试后确定的最优规模。
2. 模板目录——预制的“半成品”。Skill 不仅是规则文件，还包含一整套预制的文件结构：LaTeX 论文模
板（主文件+ 文档类+ 各章节文件）、Python 代码头部模板、目录结构（求解/论文/数据/题目）。AI 不
需要从零创建任何文件——它只需要在现有框架内填充内容。这大幅降低了AI“发挥失常”的概率。
3. 分层权限与审核模式：AI 在授权范围内连续执行，默认采用只读分析；涉及写入、删除、执行命令、联网、提交或覆盖文件时，按风险等级请求授权。低风险任务可自动执行，中风险任务在关键节点审核，高风险任务必须由人确认后执行。审核节点包括求解计划完成后、每问求解完成后、论文初稿完成后和最终提交前。
### 12.1.2 本 Skill 的设计架构——四层结构
这套数模 Skill 不是随便写了几条规则就打包的。它的设计经过了多届国赛实战验证，核心架构是四层结构：
> **Skill 四层架构（从底层到顶层）：**

| 层级 | 内容 | 设计目的 |
| --- | --- | --- |
| 第 1 层：目录骨架 | 求解/、论文/、题目/、数据/四个文件夹，以及论文内部从 0.摘要.tex 到 10.附录.tex 的完整文件清单 | 让 AI 知道“产物放哪里”，避免文件散落、论文和代码混在一起 |
| 第 2 层：规则体系 | CLAUDE.md 五大模块：全自动模式、执行流程、论文规范、代码规范、异常预案 | 让 AI 知道“怎么做是对的”，压缩自由发挥空间，降低不确定性 |
| 第 3 层：模板文件 | 论文.tex 主文件、format.cls 文档类、各章节 tex 模板、Python 公共代码头部 | 让 AI 不用从零创建，只需在模板框架内填充内容 |
| 第 4 层：触发机制 | “开始求解”关键词触发全自动流程 | 让 AI 知道“什么时候开始”，无需逐步指挥 |

### 12.1.3 Skill vs 通用 AI 对话——效率差距有多大
我们用同一道2023 年国赛C 题做了对比实验，结果非常直观：
> **对比实验：Skill 全自动 vs 通用 AI 手动引导（2023 年C 题，3 问）：**
| 对比维度 | 通用 AI（手动引导） | Skill（全自动） | 差距 |
| --- | --- | --- | --- |
| 交代规则耗时 | 约 35 分钟（每次对话重复） | 0 分钟（CLAUDE.md 自动加载） | 省 35 分钟 |
| 读题 + 写计划 | 约 25 分钟（需逐条 Prompt） | 约 3 分钟（自动执行） | 快 8 倍 |
| 逐题求解（3 问） | 约 90 分钟（每问需手动引导） | 约 25 分钟（自动流转） | 快 3.6 倍 |
| 论文填充 + 编译 | 约 60 分钟（格式反复修正） | 约 10 分钟（模板自动匹配） | 快 6 倍 |
| 排版修复 | 约 40 分钟（手动排查） | 约 5 分钟（自动循环修复） | 快 8 倍 |
| 总耗时 | 约 250 分钟（4.2 小时） | 约 43 分钟（0.7 小时） | 快 5.8 倍 |
| 论文格式合规率 | 约 65%（需大量人工修正） | 约 95%（少量人工精修） | 提升 30% |

关键洞察：Skill 省下的不仅是时间——更是决策质量。通用 AI 场景下，你的精力被消耗在“交代规则”
和“修正格式”上；Skill 场景下，这些重复性工作全部自动化，你剩下的精力全部投入到模型选择、结果审
核、论文逻辑把控——这些才是真正决定论文质量的高价值环节。
 Skill 不是万能——三个你必须清楚的前提：
1. Skill 解决的是“重复性劳动”，不是“创造性决策”。模型选哪个、假设怎么设、结果怎么解读——这
些仍然需要你的建模能力。Skill 不会替你思考，它只是把你会做但不想重复做的事自动化了。
2. Skill 的质量取决于规则的质量。CLAUDE.md 中的每一条规则都是经过实战验证的——但这不意味
着它适用于所有比赛。如果某条规则与你的实际情况冲突，改规则，不要硬套。
3. Skill 需要你“会审核”。AI 全自动跑完不代表你可以完全不看。四个必审维度（模型选择/数据预处

理/结果合理性/论文逻辑链）是你必须逐项检查的——把审核当作你的核心工作，而不是”AI 做完了
我看一眼就行”。
第8–11章讲的 Claude Code、Trae、DeepSeek 是“通用工具”——它们很强，但对数学建模竞赛一无所知。不知道国赛评分标准，不知道 AHP 的 Saaty 标度，不知道论文该写成什么结构。每次对话你都得从头交代上下文：告诉 AI 赛题是什么、数据在哪、论文分几章、每章写什么、表格用什么格式、图怎么画、参考文献什么格式。光是交代清楚这些规则，可能就要花掉你半天时间——而这半天本可以用来优化模型。
这套 Skill 模板内置了约 700 行详细规则（CLAUDE.md），覆盖从读题到交论文的全流程。把赛题和数据放进去，说一句“开始求解”，AI 自动完成——读题→写计划→逐题写代码求解→写论文→编译 PDF。整个过程按授权范围连续执行，你只需要在关键节点审核输出质量。
 这套模板不是什么——三个常见误解澄清：
不是“一键出论文”的黑箱。AI 负责执行层（写代码框架、填论文模板、画图、编译），你负责决策
层（判断模型选择对不对、审核结果合不合理、把关论文逻辑通不通）。模板只处理重复性劳动，决
策权永远在你手里。
不是万能模板。模板内置的规则是“默认最优配置”——如果你的题目实际情况与模板不适配，AI 会
自行调整（这是CLAUDE.md 中明确写的规则）。模板是起点，不是枷锁。
不是替代你的建模能力。AI 能跑通代码、写出公式、填好表格，但它不知道你的模型假设是否合理、
你的结果是否在物理上有意义。前11 章学的建模知识，此刻全部用上——用来审核AI 的每一行输
出。
这套模板的核心价值——把时间花在刀刃上：

| 角色 | 主要职责 | 节省出的时间用于 |
| --- | --- | --- |
| AI（执行层） | 读题提取信息、写代码框架、批量生成图表、填论文模板、编译 PDF、修复编译错误、检查 Overfull/Underfull | 自动完成重复性工作 |
| 你（决策层） | 判断模型选择与假设是否合理、审核结果与逻辑链、把关论证表达 | 多迭代一轮建模优化、深度做灵敏度和误差分析、通读三遍打磨论证表达 |

1. 代码、图、CSV、tex 文件名一律中文。如问题一_数据预处理与描述分析.py、各城市GDP趋势对比.png、
特征相关性热力图.png。不出现英文或拼音文件名——这是为了让所有产物一眼就能看懂内容。
2. 图存求解目录，论文跨目录引用。图存求解/问题X/图片/，论文通过../求解/问题X/图片/xxx.png的
相对路径引用。图和tex 不放在同一目录——求解产物和论文章节物理隔离。
3. 论文目录只放tex+cls+fonts。不混入图片、CSV、Python 脚本——保持LaTeX 工程干净，编译时不会
因为多余文件导致冲突或混淆。
### 12.2.2 CLAUDE.md——模板的灵魂（Skill 第2 层）
CLAUDE.md 不是普通的说明文档——它是AI 的“宪法”，是Skill 的第2 层核心。AI 在每一次对话开始时自
动读取这个文件，然后严格按其中的规则执行。你不需要记住这几百条规则，AI 会替你遵守。但你需要知道这
个文件里有什么——这样当AI 的输出不符合预期时，你才能判断是规则的问题还是AI 执行的问题。
CLAUDE.md 五大规则模块详解：

| 规则模块 | 核心内容 | 作用 |
| --- | --- | --- |
| 分层权限与审核模式 | AI 在授权范围内连续执行；按风险等级请求授权；关键节点由人审核 | 在保持流程连续性的同时控制写入、删除、命令执行、联网、提交和覆盖文件等风险 |
| 执行流程 | Step 0 读题→1 写计划→2 逐题求解→3 写论文→4 编译→5 排版优化 | 完整 SOP——AI 按顺序执行任务 |
| 论文规范 | 摘要≤900 字≤1 页、正文不分点不加粗、图表 0.8 倍且必被引用、表格统一 longtable | 格式标准——覆盖评委常见扣分点 |
| 代码规范 | 先算后画、仅用 matplotlib、中文跨平台字体、每题≥4–6 图、公共头部三个工具函数 | 统一风格——代码可复用，出错率低 |
| 异常预案 | 数据缺失→分类填补/删除；模型不收敛→排查+降级算法；报错→AI 调试；编译 Error→修复重编 | 应急手册——快速恢复，避免流程停滞 |

### 12.2.3 规则体系的作用
模板设计的核心哲学——“AI 做执行，人做决策”。CLAUDE.md 中的规则压缩 AI 的自由发挥空间，把你的精力从“交代规则”中解放出来。

启动模板只需要5 分钟。关键是把材料放对位置——AI 会自动找到它们。但启动前的环境检查同样重要
——环境不对，AI 跑不起来，5 分钟启动变成5 小时排查。

## 12.3 准备阶段——复制模板，放入赛题与数据

### 12.3.1 环境准备——30 秒检查清单
赛前环境检查（比赛前一天完成，逐项打勾）：
1. Python 环境：确认Python 3.9+ 已装。必要库：pandas、numpy、matplotlib、scipy、scikit-learn、chardet。按需加xgboost、PyPDF2、python-docx。检查和补齐依赖时运行：

```bash
pip list
pip install xgboost PyPDF2 python-docx
```

2. LaTeX 环境：确认XeLaTeX 可用。如果未安装，按操作系统选择安装方式：

```bash
xelatex --version
brew install --cask mactex
apt install texlive-xetex
```

Windows 使用TeX Live。装完后编译一个测试文档确认环境正常。
3. 中文字体：确认系统有中文字体。macOS/Windows 通常自带，Linux 需手动安装。终端查字体列表确认。
4. Claude Code：确认Claude Code 已安装并登录：

```bash
claude --version
```

如果未安装，参考第8 章的Claude Code安装配置指南。
### 12.3.2 三步启动——5 分钟从零到开始求解

环境确认无误后，启动模板只需要三步：

> **三步启动（5 分钟，零配置）：**
1. 复制整个模板文件夹到你的工作目录。别在原模板上改——保留一份干净副本，下次比赛直接复用。
复制后的文件夹就是你的“赛场工作区”。命令：

```bash
cp -r 竞赛模板2026国赛
```

每次比赛一个独立副本，比完存档，下次新建。
2. 赛题PDF 放入题目/。文件名随意——AI 用PyPDF2 自动提取文字，不依赖文件名。DOCX 格式同
样支持（python-docx 读取）。如果赛题是网页版（如美赛），可以打印为PDF 后放入，也可以直接把
网页文字复制到DOCX 中放入。
3. 附件数据放入数据/。支持xlsx 和docx 格式。Excel 数据文件、数据说明文档全部放这里。注意：所
有附件都放进去，不要挑——AI 会全量读取每个文件、每个sheet，自动判断哪些是数据文件、哪些
是说明文档。
然后打开终端，cd到模板目录，启动Claude Code，说一句：“开始求解”。
AI 自动执行的动作序列（你不需要手动做任何一步）：
读取题目/下所有PDF/DOCX→提取完整题目文本（包括背景描述、数据说明、小问要求、附录信息）
全量读取数据/下所有xlsx/docx→打印每个sheet 的：行数× 列数、列名列表、每列数据类型、异常
行标注
深度数据检查：合并单元格？多级表头？空行分隔？隐藏sheet？列数不一致？
自动识别问题数量N→创建求解/问题一/图片/和求解/问题N/结果/等完整目录结构
开始写求解计划.md
 准备阶段四个最容易犯的错（每一条都是真实翻车案例）：
1. 在原模板文件夹里直接改。模板面目全非无法复用。正确：cp -r 竞赛模板2026国赛——每次独立
副本。
2. 数据放错目录。把数据放在模板根目录或“求解“目录——AI 只会在数据/下找数据文件。放错位置
=AI 读不到= 建模缺数据= 所有结果不可用。如果你不确定文件该放哪——放在数据/下一定没错。
3. CLAUDE.md 被修改或删除。这是模板的“操作系统”——删了它，AI 就退化回通用工具，不知道任
何数模规则。除非你明确知道在改什么（参考第12.7节的修改指南），否则不要动CLAUDE.md。尤其
注意：不要在CLAUDE.md 所在目录下创建另一个CLAUDE.md——Claude Code 会读取最近的那
个，可能覆盖掉模板的规则。
4. 赛题和数据没放齐就开始。AI 不会告诉你“数据少了”——它只会基于已有的数据进行建模。如果漏
放了一个关键数据文件，AI 可能生成出看似合理但实际完全错误的结果。放入所有文件后，对照赛
题附件清单逐一核对。
## 12.4 全自动求解流程

模板的设计理念是“从头到尾一气呵成”。以下按六个步骤（Step 0 到 Step 5）逐一拆解 AI 在每个阶段做什么、产出什么、你需要审核什么。每个 Step 都附有“你要做什么”——因为虽然 AI 按授权范围连续运行，但关键节点的审核决定了最终论文的质量上限。

### 12.4.1 Step 0：读取输入——数据质量决定模型上限
这是全流程中唯一不产生可见产出的步骤，但也是最重要的步骤。AI 在这一步建立对整个题目的完整理
解——如果这一步的数据理解有偏差，后面所有建模都是建立在错误基础上的。这一步的错误是最贵的——因
为它在整个流程的最上游，下游所有产出都会继承这个错误。
> **Step 0——AI 执行的四项操作（全自动，约2-5 分钟）：**
1. 读题：PDF 用PyPDF2 逐页提取文字，DOCX 用python-docx 读取。AI 会通读全部题目内容——包括
背景描述、数据说明、每个小问的具体要求、附录中的补充信息。注意：AI 读的是文本内容，如果
PDF 是扫描图片版（文字不可选），PyPDF2 读不出来——需要提前用OCR 转文字或手动输入关键
信息。
2. 全量读取数据（非抽样！）：逐个文件、逐个sheet 读取。不是只看前5 行——AI 会读取全部数据，然
后打印每个sheet 的：行数× 列数、每一列的列名、每一列的数据类型（int/float/object）、异常行（如
某行列数不一致）。这个“数据总览”是你审核Step 0 的最重要产出。
3. 深度数据检查（四项必查，CLAUDE.md 强制）：
每个sheet 的列数是否每行一致（列数不一致= 可能有合并单元格或错行——AI 会自动标注异
常行）
每列数据类型是否统一（数值列里有没有混入文字？比如”GDP“列里某行是“缺失“两个字——
AI 会标注出来）
是否有合并单元格、多级表头、空行分隔、底部备注行（这些都会导致pandas 读取时列名错位
或数据变形——AI 会汇报并尝试自动修复）
是否有隐藏sheet（Excel 的隐藏sheet 经常被忽略但可能含关键数据——AI 会遍历所有sheet 包
括隐藏的）
4. 自动识别问题数量N：从题目文本中识别“问题一”“问题二”……“问题N”的边界，确定N 值。识别逻
辑基于关键词匹配和段落结构分析——如果题目用“第1问”“Task 1”等非常规表述，AI 也能识别。
Step 0 你要做什么——审核数据总览的四个关键点：
Step 0 阶段AI 不会问你任何问题（全自动模式），但你在看AI 打印的“数据总览”时，应该快速检查
四件事。这四件事花你3 分钟，但可能避免D2 一下午的返工：
问题数量对不对？AI 识别的 N 是否与你读题的理解一致？如果 AI 漏识别了一个小问（比如题目写“请进一步讨论……”被 AI 判定为不是独立问题），后续建模就少做了一个问题。
数据类型判断对不对？数值列被AI 识别为object 类型→可能是列里混入了文字→数据需要清洗。
反过来，分类变量被识别为数值（如“城市编号”被当成数值1/2/3）→可能被错误地用于数学运算→
建模结果无意义。
数据规模是否合理？行数、列数是否与你对题目的理解一致？如果某个sheet 只有3 行——可能是多
级表头，AI 需要特殊处理（跳过前几行，用正确的行做列名）。
是否有隐藏sheet 被遗漏？对照原始Excel 文件，确认AI 读取了所有sheet（包括隐藏的）。如果AI
汇报“发现了N 个sheet，其中M 个为隐藏sheet”——这M 个隐藏sheet 可能含关键数据。
### 12.4.2 Step 1：求解计划——先动脑再动手
AI 读题后不会立刻写代码，而是先产出求解计划.md——一份执行级路线图。这相当于你带队参赛时“拿到
题目先讨论半天再分工”——AI 把这个讨论过程结构化，让你在写代码之前看到全貌。这是全流程中你最有话语
权的时刻——现在改方向只需要改文档，代码写完再改方向是灾难。

求解计划.md——六章结构详解（每章缺一不可）：
1. 题目总体方向（一整段，不分点）：问题类型（优化/评价/预测/分类）→核心任务→数据规模→研
究递进逻辑。这段读完应该能回答“整套题在考什么能力”——是考建模深度？数据处理广度？还是
跨学科知识整合？
2. 各题求解思路（每问独立一段，文章风格不分点）：具体分析（该问的输入数据是什么？输出结果是
什么？核心难点在哪？在整套题中的定位是什么？）+ 建模方案（核心公式是什么？为什么选这个方
法而不是备选方法？）。末尾附表：主方法（名称+ 适用理由）、备选方法（名称+ 什么情况下启用）、
关键算法/工具（名称+ 用途）。这张表是求解计划中最该仔细审核的部分——方法选错了，后面全白
做。
3. 各题输出标准（含图表规划+ 预期输出）：每问必须产出的：图表清单（图1-图N，每张图的类型+
内容描述+ 横纵轴含义）、表格清单（表1-表N，每张表的内容+ 行列结构）、数值结果清单（每个
关键数字的变量名+ 预期量级）。例如“问题一需产出：数据分布直方图（6 个子图，每个数值特征一
个）、缺失值热力图、各特征箱线图（6 个子图）、相关性热力图（8×8 矩阵）、主成分方差解释柱状图、
前两个主成分散点图”。
4. 操作步骤（含依赖顺序，每问独立链路）：每问从数据加载→预处理→建模→求解→输出的完整
链路，每步标注预计耗时。关键：标注数据在问题间的流转——问题1 输出预处理数据.csv→问题
2 以此为输入→问题3 用问题2 的某结果做参数。依赖链路清晰了，求解顺序才不会乱。
5. 文件清单（中文命名，全部预先列出）：代码文件名、图文件名、CSV 文件名。全部预先列出，求解阶段AI
严格按清单生成——不遗漏、不多余。例如：问题一_数据预处理与描述分析.py、各城市GDP趋势对比.png、
特征相关性热力图.png。
6. 异常预案（6 类常见异常+ 每种2-3 条应对）：数据缺失→按MCAR/MAR/MNAR 分类处理。模型
不收敛→排查数据流→降级算法。代码报错→贴AI 调试→简化复现→降级算法。结果不合理
→输入检查→数据切分检查→公式实现检查→超参数检查→评估指标检查→简单基准对比。时
间落后→断臂保核心（舍弃次要对比/灵敏度/调参/次要小问/华丽排版）。队员突发状况→任务接手
+AI 辅助。
 Step 1 的核心价值——也是你可能最想跳过、但最不该跳过的步骤：
如果计划里的模型选择有问题，现在改只需要改文档。代码写完了再发现模型选错了，返工成本是指
数级的——代码要重写、结果要重算、图表要重画、论文对应章节要重填。花15 分钟认真看一遍求解计划，
可能省下D2 一整天的返工。
审核求解计划的三个关键问题（逐条对照，一条不通过= 计划需要修改）：
每个小问的模型选择是否匹配问题类型？预测题用了评价方法→方向性错误。优化题没写约束条件
→模型不完整。分类题没讨论类别不平衡→结果不可靠。
数据流转是否合理？问题2 的输入是否真的能从问题1 的输出得到？是否有关键中间数据被遗漏、没
有在问题间传递？
图表清单是否覆盖了主要分析维度？每问至少4-6 张图，且图与图之间不重复（不是同一数据画三张
不同风格的图凑数）——每张图回答一个不同的分析问题。
### 12.4.3 Step 2：逐题求解——从问题一到问题N
确认计划后，AI 从问题一开始逐个求解。每个问题一个独立的Python 文件，中文命名，独立可运行（可以
单独调试任何一问，不需要从头跑全部）。求解顺序严格遵守问题间的依赖关系——问题1 先跑，产出共享数据
（预处理数据.csv）后再跑问题2。

Step 2——每个问题的求解标准流程（两阶段执行，先算后画）：
第一阶段：纯计算（先算——约占总代码量的60%）
1. 数据加载→预处理→建模→求解→得到所有数值结果。每一步之间打印关键信息，方便你追踪进
度。如果某步出错，AI 能精确定位出错环节。
2. 打印每组数据的描述性统计量（CLAUDE.md 强制）：min/max/mean/std/CV（变异系数）/amplitude（极
差）。这些统计量是论文“结果分析“和“数据说明“章节的直接素材——不需要你手动再算一遍。例
如：GDP: min=2.3, max=4.7, mean=3.4, std=0.82, CV=0.24, amp=2.4。
3. 灵敏度分析前置（在求解阶段就做，不在论文阶段补）：测试关键参数（如随机森林的树数量、XGBoost
的学习率、正则化系数）在±10% 和±20% 扰动下对结果的影响。记录最佳参数组合，供论文第6章“模型检验”直接引用。为什么前置？因为灵敏度分析需要反复运行模型——在论文阶段才补做，意味
着论文写一半还要回去调代码，打断写作流。
第二阶段：检查+ 绘图（后画——约占总代码量的40%）
1. 确认所有数值结果合理：量级对不对？趋势方向对不对？正负号对不对？与常识或文献是否一致？如
果有明显不合理的结果——在终端告诉AI，AI 会回溯数据流逐段排查。
2. 每种分析结果都画图，每题至少4-6 张，多多益善。覆盖主要图表类型：柱状图（类别对比、分组对
比）、折线图（趋势变化、时间序列、算法收敛曲线）、热力图（相关性矩阵、二维密度）、散点图（两
变量关系、聚类结果、PCA 投影）、饼图（占比构成）、箱线图（多组分布对比、异常值展示）。
3. 图片自动保存到求解目录，论文通过相对路径引用。每张图保存时自动设dpi=300、bbox_inches='tight'
裁白边、中文文件名。
问题间数据流转规则（CLAUDE.md 强制）：
问题1 输出求解/预处理数据.csv→后续所有问题直接加载这份清洁数据（不用每个问题重复做数据
清洗——既省时间又保证数据一致性）
每完成一个问题→AI 立即打印该问的关键数值结果和图表清单→你快速审核确认→AI 继续下一问
如脚本报错→AI 自动读取Traceback→自行修复→重跑→通过后再下一问（不会因为一个Bug 卡
死全流程，也不需要你手动调试）
如中文渲染警告（Glyph missing from font）→AI 自动修正字体配置并重跑
求解阶段你需要做的——每问产出后的三项快速审核（每问约2-3 分钟）：
数值结果是否合理？量级对不对（GDP 预测为负数→不合理）？正负号对不对（相关系数应该在-1
到1 之间，超出→不合理）？与常识是否一致（越贵的房子面积应该越大，如果模型给出相反的结论
→排查数据）？如果看着不对——在终端告诉AI 哪里不对，AI 会自动排查数据流，定位问题环节。
图表是否专业？中文是否正常显示（无方框）？配色是否区分度高（不同类别用不同颜色，灰度下
也能区分）？坐标轴有没有物理量标签+ 单位（不能只写“GDP”，要写“GDP（万亿元）”）？图例是否遮
挡了关键数据点？有没有画set_title（违规——标题应由论文caption 承担）？
结果是否完整？每个小问的要求都做到了吗？有没有小问被遗漏？产出的图表数量和类型是否覆盖了
求解计划中列出的清单？
### 12.4.4 Step 3：写论文——按规范逐章填充
全部求解完毕后，AI 按CLAUDE.md 中的论文规范逐章填充tex 文件。论文目录预置了完整的LaTeX 工程
——主文件、文档类、字体、各章节tex 模板（Skill 第3 层）。AI 不需要从头创建LaTeX 工程，只需要在模板框
架内填充内容。这大幅降低了格式出错的概率——因为模板本身已经是正确的，AI 只需要填入正确的文字、公
式和数据。

Step 3——论文生成的七个关键规则（CLAUDE.md 强制）：
1. 按N 动态调整章节。主文件5.模型的建立与求解.tex按问题数N 动态\input对应子文件。N>4 自动
新建，N<4 自动删除。
2. 每个问题严格拆为两个子文件，但建模和求解必须在一起。5.X.1.分析与准备.tex（具体分析+ 流
程图+ 模型准备）和5.X.2.建模与求解.tex（模型建立+ 模型求解）。建模和求解必须在同一文件
——求解大量引用建立的公式/变量/参数，拆开会符号断裂。
3. 流程图固定9 框TikZ 模板，只替换文字。AI 只替换每框中的文字（≤7 汉字），箭头方向、节点位置、
连线代码一字不改。这保证了全论文所有流程图风格完全一致——不需要你手动调任何TikZ 参数。
4. 数据预处理只在问题1 写。问题2 及以后直接说“采用问题1 预处理后的数据集”，不再重复描述缺
失值处理、标准化等步骤。论文不是流水账——同一件事不说两遍。
5. 算法选择含多维度对比表（问题1 必写）。必须解释“为什么选A 方法而不是B/C 方法”——含至少
3 种候选算法的longtable 格式对比表，评估维度根据问题类型选择（优化类：全局搜索/收敛速度/约
束处理/稳定性；预测类：预测精度/训练效率/可解释性/鲁棒性）。不写“本文采用AHP方法”就完了
——评委认为你只会这一个方法。
6. 模型建立占论文最大篇幅。优化类必含完整三要素（目标函数+ 决策变量+ 约束条件）——公式完整
写出，不可用文字概括。每个编号步骤至少6-7 个公式，从基本形式逐步推导到最终形式，中间不可
跳步。公式之间用“将式(X)代入式(Y)可得”“由XX性质可知”“进一步展开得”等文字串联。
7. 所有生成的tex 文件只含可编译的LaTeX 代码。不能出现”（此处填XX）””...（提示语）“等模板指
令——AI 直接输出最终内容，tex 文件拿过来就能编译。
Step 3 你要做什么——论文初稿完成后的全局审核：
论文初稿生成后，不要急着编译——先通读一遍，检查三个全局性问题：
符号是否全论文统一？翻到符号说明表，对照正文中的每个公式——同一个参数是否从头到尾用了同
一个符号？建模手在代码里用w、论文里用θ、符号说明表里用β——这是最常见的符号混乱，AI 在
不同段落独立生成时容易犯。
图表是否全部被正文引用？搜索全文每个\ref{fig:和\ref{tab:——确认每个引用前都有“如图X
所示”或“如表X所示”的文字引导。未被引用的“幽灵图”评委根本不会看——要么补引用，要么删
图。
逻辑链是否从头到尾不断？从“问题分析”→“模型假设”→“模型建立”→“模型求解”→“结果分析”→”
结论”——这六步之间有没有跳跃？如果读到一个地方突然觉得“怎么就到这了”——说明逻辑链断了，
让AI 补上过渡推理。
### 12.4.5 Step 4：编译PDF——必须零Error
论文写完后，AI 自动进入编译阶段。编译是检验论文质量的硬性关口——任何LaTeX 语法错误都会导致编
译失败或PDF 损坏。这一步不需要你操作，但你需要理解编译流程——因为如果编译报错，你需要判断是AI 修
不了的深层问题还是普通的拼写错误。
Step 4——编译流水线（4 条命令，AI 自动依次执行）：

```bash
cd 论文
xelatex -interaction=nonstopmode 论文.tex # 第1遍：扫描全文，写aux/toc文件
xelatex -interaction=nonstopmode 论文.tex # 第2遍：读取aux，填交叉引用编号
grep -c 'Error' 论文.log
# 检查错误数——必须为0
# 如果Error > 0：
```

如果Error大于0，AI自动从.log文件中定位第一个Error的行号和内容，回溯到对应.tex文件，修复缺宏包、命令拼写错误、括号不配对或文件路径错误，然后重新编译两遍并再次检查，直到Error等于0。
关键理解——为什么编译必须跑两遍：
第一遍：LaTeX 扫描全文，把所有\label{}定义的位置和编号写入.aux 辅助文件。此时\ref{}的位
置还是“??”——因为编号还没算出来。
第二遍：读取.aux 文件，把正确的编号填到每个\ref{}的位置。所以首次编译后看到引用全是”??“是
正常现象——再编一遍就全部正确了。
如果修改了任何\label{}或\ref{}——需要再编译两遍（因为标签位置和编号都可能变了）。
### 12.4.6 Step 5：排版优化——自动修复直到日志干净
编译零错误只是及格线。一本专业的论文还需要排版干净——没有文字溢出右边界（Overfull hbox）、没有
大片空白（Underfull vbox）、没有图表超出页面（Float too large）。这一步AI 全自动循环执行，无需你手动调整
任何排版参数。
Step 5——自动排版优化循环（AI 执行，直到日志干净）：

```bash
# AI 自动执行以下循环：
while true; do
grep 'Overfull\|Underfull\|Float too large' 论文.log
  xelatex -interaction=nonstopmode 论文.tex
  xelatex -interaction=nonstopmode 论文.tex
  if ! grep -q 'Overfull\|Underfull\|Float too large' 论文.log; then
    break
  fi
done
```

根据warning类型自动修复：

- Overfull hbox in table：调整列宽比例、缩小字号或缩短格子文字。
- Overfull hbox in paragraph：用 `\url{}` 包裹长URL，或在长单词适当位置加入 `\-` 断词点。
- Float too large：缩小图的 `width` 参数或调整宽高比。
- Underfull vbox：调整段落、允许自然分页或增加内容填充。

终止标准：日志中无Overfull hbox、无Underfull vbox、无Float too large；排版紧密（页面利用率高，底
部不空大半页）；图表位置合理（不跨节、不堆叠、不单独占一页）；全文无大片空白区域。
Step 5 常见修复手段速查（了解即可，AI 自动处理）：
表格溢出（Overfull hbox in table）：调整列宽比例（严格按总比例=1.04-0.04×N 列规则）→如果还
溢→缩小表格整体字号（\zihao{-5}）→如果还溢→缩短格子内文字（用缩写替代全称）→如果
还溢→拆表为两段。
图片太大（Float too large for page）：先试缩小width 参数（0.8→0.7\textwidth）→如果还大→用[H]
强制固定在当前位置（防止浮动到大页面导致溢出）→如果还大→检查图片宽高比是否合理（太高
的图容易溢出，考虑裁剪或调整figsize）。

CLAUDE.md 中定义了非常详细的论文写作规范（约 300 行）。这里提取最关键的执行标准和常见扣分点
——不是让你背下来（AI 会自动遵守），而是让你在审核论文时知道重点看什么地方。
### 12.5.1 六条绝对禁止——违反任一条必定扣分
以下六条是国赛论文格式评分的硬性标准。AI 在CLAUDE.md 约束下基本不会违规——但你在终审时仍然
要逐条过一遍，因为AI 在某些边缘情况下（比如表格内容特别多、某段论证特别长）可能“自以为聪明“地绕过
规则。
> **论文六条红线（逐条记住，终审时逐一打勾确认）：**
1. 正文禁分点符号。不能出现”1. 2. 3.“或”“等分点格式——一律写成自然段落。这是国赛论文与课程
报告最直观的区别。唯一的例外：模型假设（允许itemize）、模型评价（允许itemize）。这两处之外
出现任何分点符号都是违规。
2. 正文禁加粗（极其严格）。\textbf{}的使用范围被限制到只有两处：摘要中的“对于问题X”（每问
段落的开头）、问题重述中的“问题N：”（每问概述的开头）。正文中任何“我们的模型”“本文提出””
综上所述“等加粗都是违规。如果你不确定某处该不该加粗——不加。
3. 章节间禁\newpage。让LaTeX 自然分页——人为断页会制造大片空白，排版极不专业。全文任何位
置（章与章、节与节、子节与子节之间）一律不加newpage。如果发现某节末尾有大片空白——不是
加newpage 的理由，而是应该调整内容让排版更紧密。
4. 图内禁set_title()。图标题由论文的\caption{}承担——图文件本身不画任何标题。图内只允许出现：
数据曲线/柱子/色块、坐标轴标签（含物理量+ 单位）、刻度数字、图例（全中文标注，说清楚每条
线/每根柱子/每个颜色代表什么）。
5. 表格格子禁换行。每个格子的文字必须在同一行显示——换行的表格又丑又难读，而且大概率是因为
列宽设置不合理。解决办法不是缩小字号（评委要能看清），而是调整列宽比例分配（给文字长的列
更多宽度）。
6. 摘要禁超一页、禁超900 字。摘要超一页是国赛最常见的格式扣分项——而且是最容易检查的（评委
翻到第二页看到摘要还在继续，直接扣分）。编译后必须用一页验证命令确认PAGE==1。如果PAGE>1：
按比例缩减各问题字数（优先缩减建议总结型问题→数据分析型问题→建模求解型问题），重新编
译，直到恰好一页。
### 12.5.2 摘要——”20 秒决定论文命运”
摘要是评审的第一关。评委在初筛阶段平均每篇论文只看20-30 秒——在这个时间内，他基本只看摘要。摘
要不行，正文写得再好也没有被细读的机会。这不是夸张——这是从多位国赛评委口中直接确认的事实。
摘要核心规范——四要素+ 三种类型模板+ 一页验证：
字数硬约束（编译后必须验证）：
开头段（背景+ 总体方法概述）≤30 字
各问题段（总计扣除头尾后约850 字，按问题类型弹性分配）

结尾段（总结+ 意义）≤20 字
总计≤900 字，必须恰好1 页（编译后用命令验证PAGE==1）
各问题字数按类型分配（850 字在各问题间分配）：
建模求解型（优化/预测/分类/评价）：≈30-35% 篇幅——方法描述（30%）+ 求解过程（30%）+ 数值
结果（40%）。这是论文的核心，应该占摘要最大篇幅。
数据分析型（统计/探索/可视化）：≈20-25% 篇幅——数据处理（30%）+ 关键发现（40%）+ 结论（30%）。
突出数据中的模式和规律。
建议总结型（建议/总结/改进）：≈10-15% 篇幅——基于前文结果的核心结论（50%）+ 建议要点（50%）。
一笔带过，不需要展开。
每问三种类型模板（AI 根据问题特征自动选用对应类型）：
有数据型（题目提供附件数据，含预处理→建模→求解全流程）：“针对问题X，本问是【类型】问
题，需【要求】。首先对附件数据预处理，提取【特征名称】，【清洗/标准化等操作】。接着【变量筛选/降
维/参数选择】。然后采取【模型名称】进行【求解过程描述】。最后【对比/验证/排序方式】，给出【输出内
容】。结果讨论显示，【关键数值结果】，模型有效地【评价结论】。”
无数据型（无附件数据，直接建立机理/方程/优化模型）：“针对问题X，本问是【类型】问题，需【要
求】。首先分析【机理/物理过程/目标约束】，建立【方程/动力学/优化模型】。接着设定【参数名称/初始条
件】。然后通过【数值方法/仿真工具/求解算法】进行求解，得到【结果概述】。结果讨论显示，【关键数值
结果】，模型有效地【评价结论】。”
建议型（基于前文结果给出建议/策略/总结，一笔带过）：“针对问题X，本问是建议总结问题，需【要
求】。基于前文分析，从【角度1】和【角度2】出发，给出【建议数量】条建议。核心结论为【要点概括】。”
一页验证命令（编译后必做，CLAUDE.md 强制）：

```bash
PAGE=$(grep 'abstract:end' 论文/论文.aux | grep -oE '\{[0-9]+\}' | head -1 | tr -d '{}')
if [ "$PAGE" -gt 1 ]; then
  echo "摘要超出一页（第${PAGE}页），需缩减"
fi
```
 摘要最常见的四个致命问题（每一条都是评委直接扣分的理由）：
1. 全是定性描述，没有具体数字。“模型效果良好”“预测精度较高”“结果令人满意”——好是多少？高
是多高？满意是多满意？每小问至少给出1-2 个具体数字：RMSE=0.XX、准确率=XX%、最优值为
XX 万元、排名第一的是XX 市。有数字的摘要= 有实质内容的论文。没数字的摘要= 什么都没说的
论文。
2. 只写做了什么，没写得到什么。“本文建立了层次分析模型，采用TOPSIS 进行综合评价”——然后
呢？权重最大的是哪个指标？排名第一的是哪个方案？综合得分是多少？评委关心的是“你发现了什
么”，不是“你用了什么工具”。
3. 篇幅分配不当。大段讲研究背景和意义（这些应该在引言里），关键的方法描述和结果数据一笔带过。
评委在20 秒内要找的是：什么方法→什么结果→什么结论。背景信息5 秒就够了。
4. 编译后超出1 页却没有发现。这是最冤的扣分——内容没问题，格式没问题，但摘要多出了3 行到第
2 页。编译后必须用一页验证命令检查PAGE 是否==1，如果>1 立即缩减。

### 12.6.3 绘图规范与配色标准
图表美观四原则（AI 自动遵守，你审核时作为检查清单）：
1. 配色专业：用内置科学colormap——定性数据用Set2/Set3/tab10（颜色间有足够区分度），顺序数据用
Blues/YlOrRd（越深= 越大，人眼直觉理解），发散数据用RdBu_r（红正白零蓝负，学术标准）。绝
对禁用jet/rainbow 彩虹配色——人眼感知色相不均匀，会人造出虚假的视觉边界。
2. 网格与边框干净：浅灰虚线网格（alpha=0.3, linestyle='--'），放在数据层下方（ax.set_axisbelow(True)），
不抢数据的视觉焦点。去掉上和右边框（despine()函数）——学术图表的标准风格是只有左和下两
条轴线。
3. 图表类型全覆盖：六个基本类型全部用到——柱状图（类别对比）、折线图（趋势变化，线宽≥1.5pt+
标记点）、热力图（矩阵数据，正方形格+ 数值标注）、散点图（变量关系，alpha=0.7+ 黑边）、饼图
（占比构成）、箱线图（分布对比）。每题至少4-6 张不同的图——不是同一数据画不同风格凑数。
4. 图内只含三要素：数据（曲线/柱子/色块）、坐标轴标签刻度（含物理量名称+ 单位）、图例（全中文，
位置不遮挡数据）。不画标题（由caption 承担）、不写多余文字、不加装饰元素。

### 12.7.3 四个必审维度——AI 输出中最容易出现隐性Bug 的地方
AI 代码95% 能跑通、论文95% 格式正确。但以下四个地方最容易有隐性Bug——代码没报错、论文编译通
过了，但建模逻辑是错的、结果是没意义的。这是你作为“决策者”最重要的审核职责——也是你建模能力的用
武之地。
> **四个必审维度（AI 每完成一个阶段，你逐项检查；四个都通过才放行到下一阶段）：**
1. 模型选择是否匹配问题类型？（求解计划阶段审核）AI 有时推荐“看起来合理但实际不适用的方法”
——比如线性回归用于明显非线性的数据、AHP 用于指标间有强相关性的场景、GA 用于简单枚举就
能求解的小规模问题。你对题目的理解比AI 深——如果觉得模型选得不对，直接告诉AI 换方法并
说明理由。不要因为“AI推荐的”就不敢质疑——AI 没有真正理解你的数据和问题背景。
2. 数据预处理逻辑是否正确？（Step 0 和Step 2 阶段审核）缺失值填补方式（均值vs 中位数vs KNN——
对应MCAR/MAR/MNAR 三种不同缺失机制）、异常值处理策略（删vs 标记vs 保留——比赛数据中
的“异常值”可能是建模的关键信号）、编码方式（有序变量用Label、无序变量用One-Hot、高基数变
量>20 类别用目标编码或频次编码——选错编码会扭曲数据中的真实关系）。对照第1-2 章的数据预
处理知识逐项审核。
3. 结果在物理上有意义吗？（每问求解完成后审核）算出来的数字量级对吗？（GDP 预测不能为负、概
率不能<0 或>1、距离不能为负）。趋势方向合理吗？（价格和销量一般是负相关，如果模型给出正相
关→排查数据或模型）。与文献或常识是否一致？（如果文献中类似问题的RMSE 约为0.1 而你的模
型RMSE 是10→量纲或单位可能出错了）。“代码没报错“不等于“结果正确”——AI 可能写了语法
正确的代码但求解了逻辑错误的问题。
4. 论文逻辑链是否完整？（论文初稿完成后审核）假设→建模→求解→结果分析→结论这条线能不
能从头到尾不断？AI 可能写出“假设合理→因此结果正确”这样跳跃的论证——中间缺了“模型为什
么有效”“结果为什么可信“的证据链。你通读时如果觉得某一段“跳过去了”——就是逻辑断裂——
让AI 在断裂处补上过渡推理、中间验证或引用支撑。

## 结论

这套竞赛 Skill 的本质：把数学建模竞赛中重复性最高的环节（读题提取信息→搭代码框架→批量画图→填论文模板→编译排错→排版优化）全部自动化。你从“写代码的人”变成“做决策的人”——审核 AI 的输出、判断方法是否合理、把关论文逻辑。

Skill 的核心设计哲学是四层架构：第 1 层目录骨架（产物归位）→第 2 层规则体系（压缩 AI 自由发挥空间）→第 3 层模板文件（AI 只填充不创建）→第 4 层触发机制（一句“开始求解”启动全流程）。四层层层递进，各司其职。

模板只处理执行层，决策层永远在你手里。记住四个必审维度（模型选择/数据预处理/结果合理性/论文逻辑链）——这是从“会用模板”到“用好模板”的关键分水岭。

前 11 章教你建模方法，第 8–11 章教你 AI 工具，这一章把两者整合成一条无缝衔接的生产线。建模方法+AI 工具+Skill 模板=完整的竞赛力。比赛的胜负，在比赛前就已经决定了 80%——剩下 20%，是你面对 72 小时的从容与笃定。

## 第12章练习

1. 全流程实战：复制模板，找一道往届国赛真题（推荐 2023 年 C 题），走通全流程：环境检查→准备→求解计划审核→逐题求解审核→论文填充→编译 PDF→排版优化。记录每步耗时和发现的问题（至少记录 5 个具体问题及其解决过程）。
2. 求解计划审核训练：分析 AI 生成的求解计划.md，找出至少两处可改进的地方（方法选择不当/步骤顺序不合理/输出标准不完整/数据流转链路有漏洞），实际修改后让 AI 重新生成计划，对比改进前后的求解结果和论文质量差异。写一段不少于 500 字的改进分析。
3. 论文规范对照检查：用 AI 跑完一篇完整论文后，对照本章“各章节写作要点速查表”，逐章检查：(1) 图表文件名是否为中文；(2) 正文是否出现分点符号或违规加粗；(3) 每张图表是否被正文引用（搜索所有 ref）；(4) 摘要是否超出一页（用一页验证命令）；(5) 表格列宽总比例是否正确。列出所有违规项并让 AI 逐一修复。
4. 代码质量对比：选一个求解脚本，将 AI 生成的代码和人工手写的代码做同一问题的功能对比。从代码结构、错误处理、图表美观度和可维护性四个维度打分，分析 AI 代码的 3 个优势和 3 个不足。
5. 修改 CLAUDE.md 实验：选择一条“安全改动”（如改图表宽度为 0.9 倍或允许 2×2 子图布局），修改 CLAUDE.md 后用同一道题重新求解。对比改动前后的论文排版和图表质量。再选择一条“危险改动”（如修改执行流程顺序），观察改动对全流程的连锁影响。写一段不少于 800 字的实验报告。
6. 效率对比实验：同一道题分别用“Skill 全自动”和“纯人工+通用 AI 辅助（不用模板，每次手动交代规则）”两种方式求解并写论文。从总耗时、论文格式合规率、图表质量、个人精力消耗四个维度对比，计算 Skill 的时间 ROI，并说明省下的时间用在了哪些高价值环节。
7. 应急处理训练：在 Skill 按授权范围运行过程中，刻意制造以下三种干扰（每次只制造一种，观察 AI 的反应）：(1) 把数据文件改名或改格式；(2) 在生成代码后故意修改其中一行导致逻辑错误；(3) 在论文 tex 中故意删掉一个括号。记录每种场景下 AI 的处理方式和你的介入点，总结“哪些情况 AI 能自己处理、哪些必须人工介入”。
