国赛C题近年趋势非常明确：大数据 + 跨学科融合。数据量大（动辄数万条记录），问题涉及多个学科交叉——医学 + 统计 + 机器学习、农业 + 经济 + 优化。C题是选题人数最多的题目，因为“给定数据”而非“推导公式”的门槛看起来更低。但C题的高分门槛反而更高：数据量大意味着竞争激烈，分析方法上的细微差异可能就是获奖与不获奖的分水岭。

本章讲解两道典型C题：NIPT检测（大数据 + 分类）和农作物种植策略（大数据 + 优化融合）。解题套路参见第3—7章算法核心。

## 14.1 C题：NIPT检测（大数据 + 分类）

### 14.1.1 赛题原题

> **材料标识：** 以下为官方题面信息的教材化转述；后续“解题路线”、参数和结果属于教材解析或示范内容，不应与官方题面混同。

**2023年高教社杯全国大学生数学建模竞赛C题——基于cfDNA的NIPT染色体异常检测**

无创产前检测（NIPT）通过抽取母体外周血，分析其中游离胎儿DNA（cfDNA）片段，判断胎儿是否存在染色体异常。赛题提供了一批模拟的基因测序数据，包含正常样本和异常样本（21三体综合征）的cfDNA测序信息。具体要求：

1. 对原始测序数据进行质量控制和预处理，提取有效特征。
2. 建立分类模型，利用cfDNA数据判断胎儿是否存在染色体异常。
3. 分析模型的稳定性与泛化能力，评估精确率、召回率等指标。
4. 撰写建模报告，详细阐述数据处理、特征筛选、模型构建与结果分析全过程。

### 14.1.2 赛题背景与数据特征

- **题目类型：**2023年国赛C题。
- **核心问题：**无创产前检测（NIPT）通过分析母体血液中游离DNA片段（cfDNA），检测胎儿是否存在染色体异常（如21三体综合征）。赛题提供大量基因测序数据——每个样本有数万个DNA片段的位置和测序深度信息。
- **数据特点：**高维度（特征维度可达数万，每个DNA片段位置是一个特征）、类别不平衡（异常样本远少于正常，异常率可能低于1%）、结构化表格数据（样本 × 特征矩阵）。

### 14.1.3 解题路线——从基因数据到分类结果

#### Step 1：数据预处理与特征工程（第1—2章）

基因数据最棘手的是“维度灾难”：特征数（数万个DNA位置）远超样本数（通常几百到几千），不能把原始数据直接丢进模型。

**关键处理：**

1. **归一化：**每个样本测序深度不同，需做文库大小归一化（RPKM/TPM标准化或Z-Score标准化），消除不同样本间总测序量的差异。
2. **特征筛选（第2章第4节）：**计算每个DNA片段位置的方差。大部分位置在所有样本中测序深度几乎一致、没有区分度，应直接删除。再用互信息筛选与目标（是否异常）有依赖关系的特征，过滤后特征数从数万降至数百。
3. **PCA降维（第2章第5节）：**对筛选后的特征做PCA进一步压缩，取能解释80%—85%方差的主成分数（通常20—50个），显著缓解维度灾难。

**严格防止数据泄露：**

所有会从数据中学习参数的步骤，包括归一化参数、方差阈值筛选、互信息筛选、PCA变换、Target Encoding和SMOTE，都必须封装在交叉验证流程中。先划分训练集与测试集；每个训练折内单独拟合预处理和特征工程，再将同一折得到的变换应用于验证折。验证集和测试集不能参与任何统计量计算或过采样。Target Encoding只能在训练折中按目标变量统计编码，验证折使用训练折得到的映射；SMOTE只能作用于训练折，不能对验证折或测试集过采样。这样才能保证模型评估反映真正的泛化能力。

### Step 2：处理类别不平衡（第4章第2节）

异常样本占比可能不到1%，直接训练会导致模型“把所有样本判为正常就能拿到超过99%的准确率”。处理策略如下：

- **SMOTE过采样：**使用$k=5$个最近邻，通过插值合成新的异常样本，而不是简单复制。
- **类别权重：**在损失函数中给异常样本更高的误分类惩罚。
- **评估指标：**弃用准确率，改用F1分数和AUC-ROC（第4章第3节）。在极度不平衡场景下，还应重点报告PR曲线及其面积，因为ROC可能过于乐观。

### Step 3：分类模型建立（第4章）

- **Baseline：逻辑回归。**降维后特征数为20—50个，适合先运行逻辑回归作为可解释的Baseline，观察哪些主成分对分类贡献最大，以及权重符号是否符合生物学常识。
- **主力模型：RF或XGBoost（第5章第4节）。**基因数据中很可能存在非线性关系和高阶交互效应，逻辑回归的线性边界可能不够。RF/XGBoost可以捕捉非线性模式，并输出特征重要性排序，识别判断异常的关键DNA片段位置，这本身也是重要的生物学发现。
- **多模型对比：**在同一测试集上对比LR、RF和XGBoost的F1和AUC。测试集只能在最终模型确定后使用一次；模型选择和超参数调整应在训练集内部通过交叉验证完成。

### Step 4：模型评估与稳健性验证

输出混淆矩阵、精确率、召回率、F1和AUC-ROC等完整指标。精确率（Precision）在这里尤为重要：误判正常胎儿为异常（FP）的代价极大，可能导致不必要的羊水穿刺并带来流产风险。应使用PR曲线（Precision-Recall Curve）而非仅使用ROC作为主要评估工具，因为正负样本极度不平衡时ROC过于乐观。

### 14.1.4 AI辅助要点

- **特征筛选：**“对基因数据做方差过滤（阈值0.01）+互信息筛选（保留前200特征）+PCA（累计解释85%方差）”。所有步骤均应在训练折中拟合，避免数据泄露。
- **类别不平衡处理：**在每次交叉验证中，仅对当前训练折执行SMOTE（$k=5$），并在同一训练折内拟合类别权重；验证折和测试集不得过采样或参与权重计算。SMOTE与类别权重不应默认叠加使用，若同时使用必须通过交叉验证比较，避免对少数类重复补偿。
- **结果解释：**“分析XGBoost特征重要性Top-10对应的DNA片段位置，查阅文献讨论其生物学意义”。

## 14.2 C题：农作物种植策略（大数据 + 优化融合）

### 14.2.1 赛题原题

> **材料标识：** 以下为官方题面信息的教材化转述；后续“解题路线”、参数和结果属于教材解析或示范内容，不应与官方题面混同。

**2024年高教社杯全国大学生数学建模竞赛C题——农作物种植策略优化**

某地区下辖多个村庄，拥有多种可种植农作物（小麦、玉米、大豆、蔬菜等）。赛题提供该地区过去若干年的气象数据（气温、降水、日照）、土壤数据（土壤有机质、pH、氮磷钾）、作物产量数据和市场价格数据。具体要求：

1. 分析历史数据，揭示气象、土壤因素与作物产量之间的关系。
2. 建立作物产量和价格预测模型，预测未来一年的各作物产量及市场价格。
3. 在产量和价格预测基础上，为各村制定最优种植方案（种什么、种多少），使总收益最大，同时保障粮食安全并考虑种植风险。
4. 分析方案的不确定性（产量和价格预测误差对方案的影响），给出稳健的种植建议。

### 14.2.2 赛题背景与融合特征

- **题目类型：**2024年国赛C题。
- **核心问题：**某地区有多个村庄和多种可种植作物（小麦、玉米、大豆等），给定过去若干年的气象数据、土壤数据、作物产量数据和市场价格数据，需为未来一年制定最优种植方案——每个村庄种什么、种多少。
- **融合特征：**典型的“预测 + 优化”两阶段问题。不能直接使用优化模型，因为事先不知道“如果种X亩玉米，产量会是多少、能卖多少钱”。必须先建立预测模型（根据气象、土壤和历史数据预测各作物产量和价格），再把预测结果代入优化模型，在预测值下做最优种植决策。

### 14.2.3 解题路线——“预测 + 优化”两阶段

#### 第一阶段：预测模型（第5章）

用历史数据训练作物产量预测模型。特征包括气象变量（气温、降水、日照）、土壤变量（有机质、pH、氮磷钾）和历史产量；目标是预测给定气象和土壤条件下的产量。

**可选方法：**

- **线性回归（第5章第1节）：**快速Baseline，检验特征与产量是否大致线性。
- **XGBoost（第5章第4节）：**捕捉气象、土壤与产量间的非线性交互，例如“高温 + 干旱”对产量的联合影响远超二者单独影响之和。
- **ARIMA（第5章第3节）：**如果产量数据是时间序列，可捕捉趋势和周期性。

价格预测同样可使用上述方法，以历史价格和市场因素预测下一年价格。预测模型的训练、特征处理和误差估计必须严格按时间或训练/验证划分进行，不能使用未来信息。

#### 第二阶段：优化模型（第6章）

基于预测模型给出的各村庄—各作物预期产量$\hat{y}_{ij}$和预期价格$\hat{p}_{j}$构建优化模型。

- **决策变量：**$x_{ij}$表示村庄$i$种植作物$j$的面积（亩）。
- **目标函数（多目标）：**
  1. 总收益最大：

     $$
     \max \sum_{i,j}x_{ij}\hat{y}_{ij}\hat{p}_j
     $$

  2. 总风险最小，即考虑产量和价格不确定性的收益方差最小化。
  3. 粮食安全：主粮总产量不低于底线$D_{\min}$。
- **约束：**耕地面积约束（$\sum_{j}x_{ij}\leq$可用耕地）、轮作约束、水资源约束和劳动力约束。
- **目标—约束层次：**本题原始建模是多目标问题：总收益最大、总风险最小、粮食安全水平最大（或至少达到安全底线）。耕地、轮作、水资源和劳动力属于可行域约束。实际求解可采用 $\varepsilon$ 约束法：以总收益为主目标，将风险上限和粮食安全下限作为约束，形成一系列单目标子问题；因此，收益是目标，风险与粮食安全是约束，不改变原问题的多目标层次。

**不确定性处理（核心亮点）：**

预测模型的输出有误差，不能只用点预测做优化，应使用蒙特卡洛模拟。从预测误差分布中重复抽样（例如抽样1000次），每次抽取一组产量和价格并求解一次优化模型，得到1000组种植方案。分析方案分布：哪些决策变量在绝大多数模拟中保持一致，哪些波动很大。前者构成稳健方案，后者表明决策对不确定性敏感。

#### 防止预测—优化流程中的数据泄露

预测模型只能使用预测时点之前的历史气象、土壤、产量和价格数据；验证集或未来测试期数据不得参与特征筛选、标准化、模型训练及误差分布估计。应先完成时间切分，再在训练期拟合全部预处理和预测模型，并将预测误差仅依据训练期的交叉验证或留出验证结果估计。蒙特卡洛抽样只能从该误差分布生成情景，不能利用真实未来产量或价格反向修正情景参数。最终方案应在独立测试期或真实可用信息下评价。

### 14.2.4 AI辅助要点

- **产量预测：**“用XGBoost训练产量模型，特征 = 气象 + 土壤，采用5折交叉验证，输出RMSE和特征重要性”。若数据存在时间顺序，应优先使用时间序列交叉验证。
- **优化建模：**“用PuLP建立多目标LP模型，采用$\varepsilon$约束法，生成完整求解代码”。
- **蒙特卡洛模拟：**“从XGBoost预测误差的正态分布中抽样1000次，每次求解优化模型，统计决策变量分布并绘制箱线图”。误差分布应由训练期验证残差估计，不能使用未来真实结果。

## 14.3 C题特点与选型建议

### 表14.1 两道C题对比

| 维度 | C题（NIPT检测） | C题（农作物种植） |
| --- | --- | --- |
| 核心任务 | 分类——判断样本是否异常 | 预测 + 优化融合 |
| 数据类型 | 基因测序（高维稀疏） | 气象/土壤/产量/价格 |
| 主要挑战 | 维度灾难 + 类别不平衡 | 不确定性 + 多目标权衡 |
| 核心方法 | 特征筛选 + PCA + LR/RF/XGBoost | XGBoost预测 + 优化 + 蒙特卡洛 |
| 对应章节 | 第1—2、4章（预处理 + 特征 + 分类） | 第5—7章（预测 + 优化 + 不确定性） |
| 高分关键 | 特征筛选有依据、结果有生物学解释 | 预测与优化的桥梁设计、稳健性验证 |

### C题的性质：选题决策

C题适合擅长数据分析和编程的团队。与A题（需物理推导）和B题（需优化建模）相比，C题更偏重数据处理、特征工程和模型调优。选C题的前提是：团队熟练掌握Pandas、Sklearn、XGBoost工具链，理解数据预处理完整pipeline，理解分类/回归评估指标并能正确选择，会做特征工程。

C题高分关键不在模型复杂度，而在数据处理的专业性（特征筛选有依据、降维合理、不平衡处理正确）和结果解释的业务深度：不仅要报告“准确率95%”，还要说明“哪些特征最重要、为什么它们重要、对实践有什么启示”。

**结论：**C题核心特征是数据量大 + 跨学科融合。

- NIPT检测是分类范式：预处理 → 特征筛选 → 降维 → 分类建模 → 多模型评估。核心挑战是维度灾难和类别不平衡。
- 农作物种植是预测 + 优化融合范式：预测产量 + 价格 → 优化种植方案 → 蒙特卡洛处理不确定性。核心挑战是预测误差向优化决策的传播。
- 国赛C题的趋势是数据越来越大、问题越来越融合、评委越来越看重分析深度而非模型复杂度。

## 第14章练习

1. 阅读2023年国赛C题（NIPT）原文，设计完整分类建模方案：预处理 → 特征筛选 → 降维 → 至少3种分类器对比 → 评估（含不平衡处理）。每一步标注对应章节。
2. 阅读2024年国赛C题（农作物）原文，设计“预测 + 优化”两阶段方案：第一阶段用3种方法预测产量并对比，第二阶段建立多目标优化并求解。讨论预测误差如何影响优化决策的稳健性。
3. C题数据量大。对比“先方差过滤再PCA”和“先互信息筛选再PCA”在模拟基因数据上的降维效果和后续分类性能。
4. 蒙特卡洛模拟实战：给定XGBoost产量预测RMSE = 50 kg/亩，误差服从$N(0,50^2)$。写Python代码抽样500次，每次求解LP（最大化收益），统计最优种植面积的均值、标准差和95%置信区间。
5. C题选型分析：对比A、B、C三题特点，从数据处理、物理推导、优化建模、编程四个维度分析你的团队适合选哪一题。
6. 综合设计：设计通用“C题解题SOP”，涵盖从拿到数据到提交论文的全流程。每一步标注做什么、为什么、AI辅助什么、人工审核什么，以及参考哪一章。
