# 条目规范

> 所有进入 `library/` 的文件必须遵守本规范。`_raw/` 阶段不受此约束。

## 1. 文件命名

```
<分类代码><三位序号>_<英文或拼音短名>.md
示例：M001_two_beam_model.md
```

- 序号在一级分类内递增，不复用已删除的编号。
- 短名用 ASCII，避免 Windows/工具链中文路径问题。

## 2. Front-matter（必填字段）

```yaml
---
id: M001                # 同文件名中的代码+序号
title: 双光束干涉模型推导  # 中文标题
type: derivation        # derivation|algorithm|data|result|note|reference
tags: [干涉, 厚度反演]    # 3~8 个，可用于跨类检索
source: 交接材料/01_模型完整叙述/01-1_v1.0模型定稿推导.md  # 原文相对路径（可追溯）
date: 2026-09-09        # 摄取/整理日期
status: draft           # draft|reviewed|final  （final = 已核对原文）
links: [M002, R001]     # 相关条目 id 列表
---
```

## 3. 正文结构（推荐，不强求）

```markdown
## 摘要        # ≤3 句话说明本条目是什么
## 要点        # 结构化摘录；硬结论（数字/公式）在此层
## 原文摘录    # 需要原样保留的公式块/表格，注明原文小节
## 备注        # 疑问、口径差异、待核对项
```

## 4. 硬约束

1. **可追溯**：每个事实性陈述能通过 `source` + 原文小节定位。
2. **硬结论不改写**：数字、公式、单位原样搬运；发现不同来源数字冲突时，在"备注"登记冲突，不改任何一方，以权威源为准并在 `links` 指向权威条目。
3. **一文件一主题**：超长原文拆分时保持各条目独立可读。
4. 大文件（PDF/xlsx/图片）不复制进库，只在条目中登记路径与摘要。
