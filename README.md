# 数学建模竞赛工作区

全国大学生数学建模竞赛（CUMCM）的工作区。三人一队，三天交稿。所有资料、过程记录、最终产出都放在这里，按 00 / 01 / 02 编号组织。

## 目录结构

| 文件夹 | 放什么 | 什么时候用 |
|---|---|---|
| 00_知识库/ | 算法速查表、各模型详解、画图模板、写作规范、提示词库 | 赛前备好，比赛期间只读 |
| 01_当前赛题/ | 赛题原文、数据清洗记录、模型方案对比、论文素材 | 比赛 3 天实时更新 |
| 02_输出产物/ | 最终论文、支撑材料压缩包、AI 使用声明 | 最后一天汇总 |

各文件夹内的说明文档：

- `00_知识库/00_知识库使用说明.md` —— 知识库内容索引，以及给 AI 的读取指令
- `01_当前赛题/README_使用说明.md` —— 比赛 3 天的节奏，每天必做的记录
- `02_输出产物/README_交付清单.md` —— 交稿前的逐项检查清单

## 这套结构解决什么问题

三天比赛最容易出问题的三件事，结构就是为它们准备的：

1. **查资料慢**。知识库赛前全部备好，比赛时直接引用，不用现翻笔记、现场搜方法。
2. **做过的事记不住**。每个环节都有记录模板，每天花十分钟填一下，写论文时素材现成，不用靠回忆。
3. **AI 产出不可信**。约定是：AI 给建议，人拍板；AI 写代码，人运行；论文里的数字必须来自自己程序跑出来的结果。

## 赛前准备（比赛前两周内做完）

1. 通读 `00_知识库/` 全部文档。
2. 把文档里的代码自己跑一遍（画图模板、AHP/TOPSIS、GM(1,1)、FFT 这些），确认环境没问题。
3. 检查 Python 环境，缺的库现在装好：
   `pip install numpy scipy pandas matplotlib scikit-learn statsmodels pulp pmdarima`
4. 如果用 LaTeX 写论文，确认模板能编译。缺宏包的处理方法见 `00_知识库/中国大学生数学建模竞赛 LaTeX 模板/README.md` 的"常见问题"。
5. 放团队自己的资料：课程笔记、往年论文、常用数据。

## 比赛 3 天

按 `01_当前赛题/README_使用说明.md` 的节奏走。每天结束前固定做三件事：

1. 更新 `01_当前赛题/02_建模过程/模型方案对比.md`：今天讨论了什么方案、选了哪个、为什么。
2. 在 `01_当前赛题/02_建模过程/代码脚本/Qx/说明.md` 里写清每个脚本的用途、关键参数、运行顺序。
3. 更新 `01_当前赛题/01_数据分析/数据清洗记录.md`：处理了多少数据、怎么处理的。

这些记录是论文"问题分析"和"模型建立"部分的主要素材。评委看重真实的思考过程（试过什么、为什么放弃），这些记录写进论文就是最好的证据。

整体顺序：赛题分析 → 模型确定 → 编程实现 → 论文撰写 → 终审。赛题 PDF 和附件放到 `01_当前赛题/00_赛题原文/`。

## 对话命名规范

比赛期间会开很多 AI 对话，标题统一用这个格式，赛后写 AI 使用报告时能回溯：

```
【Q1建模】0906_评价模型_参数讨论
【编程】0906_数据预处理_去缺失值
【论文】0907_摘要_第3稿
```

## AI 使用约定

- AI 可以：读资料、解释概念、写代码、语言润色、搭框架、按清单检查。
- AI 不可以：替你们定模型和假设（只能给候选和理由）、编造任何数字、写摘要定稿。

用 Claude Code 时，工作区根目录的 `CLAUDE.md` 会在每次会话自动加载，结构、规范和红线都写在那里，不需要每次重复说明。

## 交稿前

按 `02_输出产物/README_交付清单.md` 逐项检查。最常出致命问题的几处：

- 电子版论文第一页必须是摘要页，不能放承诺书和编号页
- 正文不超过 30 页（2026 年规范），不要目录
- 附录必须有全部可运行代码，且运行结果和论文里的数字一致
- 全文任何地方（包括代码注释）不能出现学校和姓名
- AI 使用声明要附上
