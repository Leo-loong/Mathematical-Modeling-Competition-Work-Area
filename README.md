# 数模竞赛 Agent 工作区（通用模板）

> 这套架构给 3 天竞赛搭建一个「数字资料库 + 自动化流水线」。
> 核心逻辑：**把找资料的时间压缩到零，把记录过程的成本降到最低。**
> 核心原则：**AI 跑腿，人把关；AI 出稿，人改写。**

---

## 一、三层结构

```
竞赛工作区/
├── 00_知识库/       ← 静态参考资料（赛前准备，比赛时只读）
├── 01_当前赛题/     ← 动态工作区（比赛当天从模板复制，改名使用）
└── 02_输出产物/     ← 最终交付物（论文 + 支撑材料 + AI声明）
```

| 文件夹 | 内容 | 何时用 |
|---|---|---|
| 00_知识库 | 算法速查、画图模板、写作规范、提示词库 | **赛前**全部备好；**比赛第一天**让 AI 全部读一遍 |
| 01_当前赛题 | 赛题原文、数据分析记录、建模过程、图表、论文素材 | 比赛 3 天实时更新 |
| 02_输出产物 | 最终论文.pdf、支撑材料.zip、AI 使用声明 | 最后半天汇总 |

---

## 二、使用流程

### 赛前（现在 → 比赛前 2 周）
1. 把本模板复制到任意位置，改名为「竞赛工作区」。
2. 通读 `00_知识库/` 全部文档，把里面写到的模型、代码**自己跑一遍**。
3. 补充你们团队自己的资料（学校课程笔记、历年获奖论文、常用数据）。

### 比赛第一天（拿到赛题后 30 分钟）
1. 把 `01_当前赛题` 模板里的说明文档看一遍（或让 AI 读）。
2. 赛题 PDF 和附件放进 `01_当前赛题/00_赛题原文/`。
3. **开一个新对话，给 AI 发以下启动指令**：

```
请阅读我工作区中 00_知识库/ 下的所有文档，了解：
1. 我备好的算法库有哪些（模型名称、适用场景、代码框架）
2. 画图模板的代码规范和字体设置
3. 论文写作的格式要求与摘要写法
4. AI 使用规范与提示词要求
后续所有回答请基于这些资料，不要随意发挥。
如果资料里没有你要用的方法，请先说明再补充。
```

4. 按「赛题分析 → 模型确定 → 编程实现 → 论文撰写 → 终审」的顺序推进（详见下文）。

### 比赛结束前 3 小时
- 检查 `02_输出产物/` 的交付清单（见该文件夹 README）。

---

## 三、对话命名规范（便于赛后回溯）

每个新对话的标题用这个格式：

```
【Q1建模】0906_评价模型_参数讨论
【编程】0906_数据预处理_去缺失值
【论文】0907_摘要_第3稿
```

比赛结束要写「AI 使用报告」时，靠这些标题就能回溯整个过程。

---

## 四、标准工作流（每天按这个节奏推进）

```
1. 赛题分析    → 让AI提取关键信息/约束/任务清单 → 自己核对查漏补缺
2. 模型确定    → 让AI推荐模型并阐述理由 → 团队讨论拍板 → 写进模型方案对比.md
3. 编程实现    → 让AI写代码 → 自己运行核对数据/图表 → 结果存03_结果与图表
4. 论文撰写    → 用AI搭框架写初稿 → 逐字逐句改写去AI味 → 加入自己的思考过程
5. 终审合规    → AI自查表检查格式 → 写AI使用声明 → 查重初筛
```

**红线（AI 绝不能碰的部分）**：
- ❌ 替你定模型、定假设——只能给建议
- ❌ 编造结果数据——所有数字必须来自你们自己跑的程序
- ❌ 替你写摘要——摘要必须自己打磨

---

## 五、去"AI 味"三条铁律（近年评阅重点）

1. **数值说话**：「误差 10⁻⁴ 以内」>「误差很小」；「参数来自实验数据 X」> 空泛引用。
2. **讲过程**：「为了验证 XX 猜想尝试了 A，因参数过多改用 B，发现……」>「首先……其次……最后」。
3. **留痕迹**：记录你们放弃过哪些方案、踩过哪些坑——这是最真实的人类痕迹。
