**数学建模国赛【模型检验】万能提示词**

**（检测/修改/撰写三模式完整版）**

**第4步：智能匹配检验类型，对每个问题的模型进行检验，输出标准化交接包。支持检测评估模式。**

> 注：本提示词支持三种运行模式，自动检测适配：串联模式自动读取上一步「建模求解交接包」并严格遵循其方案，完成后输出本步「模型检验标准化交接包」；独立模式在无交接包时自行先简要建模求解（确定模型类型+核心结果），再进行完整模型检验，输出质量与串联模式一致；检测整改模式对上传的已有成果（检验报告/检验代码/论文中的检验章节）先与获奖级标准多维度对比检测，再按优先级（P0→P1→P2）自动整改并复检，强制输出整改后成果+HTML整改报告（含检测结果总览、多维度评分可视化、分维度详细分析、标准对照表、优先级整改清单、整改前后对比、复检结果、底部信息栏），不得只检测不整改；如只需检测不需整改，则只输出HTML检测报告。评估等级：获奖级≥90 / 一等奖80-89 / 二等奖70-79 / 省一60-69 / 省二50-59 / 需大幅改进<50。无论哪种模式，输出质量标准一致，不得因模式不同而降低质量。

**「模型检验标准化交接包」输出格式（强制）**

本步完成后必须输出以下结构化交接包（JSON格式），供下一步自动读取：

```json
{
  "各小问检验方法": "问题一:灵敏度分析; 问题二:误差分析...",
  "检验指标数值": "MAE=XXX; RMSE=XXX; R²=XXX...",
  "检验图表路径": "figs/test1.png; figs/test2.png...",
  "检验结论": "问题一:通过/不通过+结论; 问题二:...",
  "改进建议": "如不通过，具体改进方向和参数调整建议"
}
```

**一、输入（三模式）**

- 串联模式：自动读取「建模求解交接包」(模型+求解结果+检验建议)+代码
- 独立模式：模型+求解结果+代码(自行简要建模)
- 检测整改模式：上传的检验报告/检验代码/论文中的检验章节

**二、输出**

- 解题模式：①每个问题的检验报告(5.X.5子节) ②检验图表 ③检验结论 ④改进建议(如不通过) ⑤标准化交接包
- 检测整改模式：HTML整改报告（强制）

**三、智能检验类型匹配机制**

- 模型类型识别：先识别模型类型(优化/预测/评价/分类/微分方程/仿真)，再选择检验类型
- 检验类型-模型类型适配矩阵：根据矩阵选择必做/推荐/不适用的检验类型
- 检验类型选择决策流程：识别模型类型→查适配矩阵→确定必做检验→选择推荐检验→输出检验方案
- 检验类型误用警示：明确列出常见误用(如对优化模型算R²)，必须避免

**四、检验位置**

模型检验是每个问题的5.X.5子节，在模型求解(5.X.4)之后立即进行，不是单独的第六章！每问求解后立即检验，不通过则返回修正该问题模型！

**五、智能检验匹配（禁止机械套用）**

| 检验类型 | 优化模型 | 预测模型 | 评价模型 | 分类模型 |
| --- | --- | --- | --- | --- |
| 误差分析 | 不适用 | 必做 | 不适用 | 可选 |
| 灵敏度分析 | 必做 | 推荐 | 必做 | 可选 |
| 鲁棒性分析 | 必做 | 推荐 | 必做 | 必做 |
| 对比验证 | 必做 | 必做 | 推荐 | 必做 |
| 最优性间隙 | 必做 | 不适用 | 不适用 | 不适用 |
| 交叉验证 | 不适用 | 必做 | 不适用 | 必做 |

常见误用：①对优化模型算R²/MAPE ②对评价模型做交叉验证 ③小样本(<30)做K-fold ④灵敏度只扰动一个参数(至少3个)

**六、优秀论文检验共性特征**

- 检验类型智能匹配，不机械套用四大检验
- 每个检验有明确的量化指标和阈值(如MAPE<10%优秀，CV<10%稳健)
- 检验图表专业：龙卷风图/三联图/雷达图/箱线图，配色专业
- 检验结论明确：通过/不通过，不通过有具体改进建议
- 检验不通过必须返回修正模型，不得带病交付

**七、四大核心检验**

- 误差分析(仅预测/分类)：MAE/RMSE/MAPE/R²至少3种+三联图(散点+残差+分布)
- 灵敏度分析(优化/评价/微分方程)：至少3个参数±10%/±20%扰动+归一化灵敏度系数+龙卷风图
- 鲁棒性分析(绝大多数必做)：数据扰动/滚动预测/权重扰动+变异系数CV+子样本检验(≥50次)
- 对比验证(绝大多数必做)：与简化模型/文献结果/消融实验对比+雷达图+量化提升幅度

**八、模型专用检验**

- 优化模型：最优性间隙Gap+约束满足率CSR
- 预测模型：K-fold交叉验证(K=5或10)，时序用TimeSeriesSplit
- 评价模型：AHP一致性CR<0.1+权重灵敏度(Spearman)

**九、论文检验整改全流程**

- 步骤1：论文解析与模型识别——读取论文，识别每个问题的模型类型和核心结果
- 步骤2：智能检验类型匹配——根据模型类型选择必做/推荐检验
- 步骤3：逐项检查与诊断——检查每个检验是否完成、指标是否达标、图表是否专业
- 步骤4：整改方案设计——对未通过的检验，设计具体整改方案(调整模型/增加检验/修正指标)
- 步骤5：整改后复检——整改完成后重新检验，直至通过

**十、检验不通过处理**

检验不通过必须自动返回修正该问题模型，重新求解后再检验，直至通过。不得带病进入论文写作！

**十一、检测评估模式评估维度**

| 维度 | 标准要求 | 评估要点 |
| --- | --- | --- |
| 检验类型匹配 | 智能匹配，不机械套用 | 是否根据模型类型选择检验，是否有常见误用 |
| 检验方法 | 方法正确，指标完整 | 检验方法是否正确，指标是否完整，是否有量化阈值 |
| 结论可靠性 | 结论明确，有数据支撑 | 结论是否明确，是否有数据支撑，是否过于笼统 |
| 改进建议 | 具体可操作 | 改进建议是否具体可操作，是否只说「需要改进」 |
| 检验图表 | 专业，配色专业，标注完整 | 图表是否专业，配色是否专业，标注是否完整 |
| 不通过处理 | 必须返回修正 | 检验不通过是否返回修正，是否带病交付 |

**十二、本提示词整改能力（检测+自动整改）**

| 整改类型 | 可自动整改的内容 | 整改方式 |
| --- | --- | --- |
| P0致命 | 检验类型完全错误(如对优化模型算R²)、检验指标缺失、检验代码无法运行 | 修正检验类型+补充必做指标+修复检验代码 |
| P1重要 | 检验不深入(只给数字不分析)、灵敏度只扰动1个参数、无对比验证 | 完善检验分析+补充≥3个参数扰动+补充对比验证 |
| P2优化 | 检验图表配色/标注、检验报告格式、结论表述 | 美化检验图表+完善检验报告格式+学术化结论表述 |
| 需手动 | 模型本身有致命缺陷导致检验完全不通过、需要重新建模 | 给出模型缺陷分析和重新建模建议，确认后执行 |

整改后输出：修改后的检验代码_已整改.py + 检验报告_已整改.docx + HTML整改报告
