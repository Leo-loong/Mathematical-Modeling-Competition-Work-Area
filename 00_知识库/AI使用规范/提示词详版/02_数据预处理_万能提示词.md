**数学建模国赛【数据预处理】万能提示词**

**（检测/修改/撰写三模式完整版）**

**第2步：基于赛题分析的国奖版推荐模型，对数据进行适配性预处理，输出标准化交接包。支持检测评估模式。**

> 注：本提示词支持三种运行模式，自动检测适配：串联模式自动读取上一步「赛题分析标准化交接包」(国奖版推荐模型+预处理重点)并严格遵循其方案，不得随意降级或更换模型，完成后输出本步「数据预处理标准化交接包」；独立模式在无交接包时自行简要赛题分析(判断题型+推荐模型+确定预处理重点)，再基于原始数据进行完整预处理，输出质量与串联模式一致；检测整改模式对上传的已有成果（预处理代码/预处理后数据/预处理报告）先与获奖级标准多维度对比检测，再按优先级（P0→P1→P2）自动整改并复检，强制输出整改后成果+HTML整改报告（含检测结果总览、多维度评分可视化、分维度详细分析、标准对照表、优先级整改清单、整改前后对比、复检结果、底部信息栏），不得只检测不整改；如只需检测不需整改，则只输出HTML检测报告。评估等级：获奖级≥90 / 一等奖80-89 / 二等奖70-79 / 省一60-69 / 省二50-59 / 需大幅改进<50。无论哪种模式，输出质量标准一致，不得因模式不同而降低质量。

**检测整改模式运行细则**

- 触发条件：检测到输入为已有成果（预处理代码/预处理后数据/预处理报告），而非原始题目+数据时，自动进入检测评估+自动整改模式
- 功能：①将上传成果与获奖级标准多维度对比检测，评估数据诊断完整性/处理方法合理性/防数据泄露/特征工程质量/代码可运行性/预处理流程图规范性6个维度；②基于检测出的问题按提示词要求自动修改优化，消除问题
- 整改流程：①多维度检测→②生成HTML检测报告→③按优先级(P0→P1→P2)自动整改→④整改后复检→⑤输出整改后成果+HTML整改报告(含整改前后对比)
- 整改原则：能自动修改的自动修改（格式/排版/公式/图表/代码），不能自动修改的给出详细修改方案（如模型重构/创新点设计），不得只检测不整改
- 报告要求：HTML整改报告文件名「整改报告_成果名称.html」，报告最开始给出检测结果总览，然后列出整改清单+整改前后对比+复检结果
- 默认执行检测+自动整改一体化；如只需检测不需整改，则只输出HTML检测报告

**「数据预处理标准化交接包」输出格式（强制）**

本步完成后必须输出以下结构化交接包（JSON格式），供下一步自动读取：

```json
{
  "预处理后数据路径": "data/preprocessed.csv",
  "处理日志": "每列处理方法+处理行数",
  "特征清单": "原始特征+衍生特征+特征类型",
  "数据划分方案": "训练集/验证集/测试集比例+划分方法",
  "数据质量报告": "缺失率/异常率/分布特征/质量评分",
  "推荐模型适配说明": "预处理方案如何适配国奖版推荐模型"
}
```

**一、输入（三模式）**

- 串联模式：自动读取「赛题分析标准化交接包」(国奖版推荐模型+预处理重点)+原始数据
- 独立模式：原始数据+题目(自行简要分析确定推荐模型和预处理重点)
- 检测整改模式：上传的预处理代码/预处理后数据/预处理报告

**二、输出**

- 解题模式：①预处理后数据 ②完整Python代码 ③预处理日志 ④数据质量报告 ⑤预处理流程图 ⑥标准化交接包
- 检测整改模式：HTML整改报告（强制）

**三、优秀论文数据预处理共性特点**

- 预处理与模型适配：预处理方案明确说明如何适配国奖版推荐模型（如树模型不需要标准化）
- 防数据泄露：所有操作只在训练集fit，测试集transform，明确说明防泄露措施
- 特征工程有业务意义：衍生特征说明业务含义，不是盲目构造
- 完整代码可运行：代码分模块，有注释，固定随机种子，可一键运行
- 预处理流程图：强制输出预处理流程图，展示数据处理全流程

**四、数据问题类型大全**

- 缺失值：完全随机缺失(MCAR)/随机缺失(MAR)/非随机缺失(MNAR)，不同类型不同处理
- 异常值：真实异常/录入错误/统计离群，先判断真实性再处理
- 数据质量问题：重复值/格式不一致/单位不统一/编码错误/逻辑矛盾
- 分布问题：偏态分布/长尾分布/类别不平衡/共线性
- 时空问题：时间不连续/空间缺失/周期性异常

**五、预处理的常见误区（必须避免）**

- 误区1：盲目删除所有异常值（真实异常应保留）
- 误区2：用全量数据统计量处理训练集（数据泄露）
- 误区3：过度预处理，丢失重要信息
- 误区4：特征工程无业务意义，盲目构造
- 误区5：不说明预处理对建模的影响

**六、不同题型的数据预处理重点**

| 题型 | 预处理重点 |
| --- | --- |
| A/B题(机理优化) | 数据量小，重点是数据校验和单位统一，特征工程基于物理意义 |
| C题(数据分析) | 数据量大，重点是缺失值/异常值处理、特征工程、降维、防泄露 |
| D题(运筹优化) | 数据量小，重点是数据校验、约束条件数字化、参数估计 |
| E题(机理预测) | 时间序列数据，重点是时间插值、平稳性检验、特征工程(滞后/滚动) |

**七、8维度数据诊断**

- 基本信息/缺失值/异常值/分布特征/质量一致性/时空特征/数据量充足性/建模需求匹配

**八、缺失值与异常值处理**

| 情况 | 处理方法 |
| --- | --- |
| 缺失<5% | 删除或简单填充 |
| 缺失5-30%随机 | 数值型中位数，类别型众数，时序插值 |
| 缺失>30% | 删除列+「是否缺失」标记 |
| 真实异常 | 保留，可对数变换或分箱 |
| 录入错误 | 修正或删除 |
| 统计离群 | 分析后决定保留/截断/变换 |

**九、特征工程**

- 必须有业务意义的衍生特征，禁止全量原始特征直接输入
- 类别编码：低基数One-Hot，高基数序数Label，高基数名义Target编码
- 特征缩放：仅线性模型/SVM/KNN/神经网络需要时标准化
- 降维：特征过多或共线性严重时用PCA/特征选择/L1正则

**十、预处理流程图规范（强制输出）**

- 必须输出预处理流程图，包含：数据输入节点→诊断节点→决策节点(菱形，根据问题类型选择方法)→处理操作节点→验证节点→数据输出节点
- 用matplotlib绘制规范流程图，节点文字4-6字，正交箭头

**十一、数据泄露防范（强制）**

所有预处理操作必须只在训练集上fit，再transform测试集！严禁用全量数据统计量处理训练集！

**十二、代码规范**

- 完整可运行Python，固定随机种子np.random.seed(42)，分模块(data_loader/diagnose/preprocess/verify/save)
- 自动检测编码(utf-8/gbk/gb2312)和分隔符
- 输出预处理日志(每列做了什么处理、处理了多少行)
- CSV用UTF-8 with BOM编码，确保Excel打开不乱码
- 提供run_all.py一键运行脚本和requirements.txt

**十三、检测评估模式评估维度**

| 维度 | 标准要求 | 评估要点 |
| --- | --- | --- |
| 数据诊断 | 8维度完整诊断 | 是否覆盖所有诊断维度，诊断是否深入 |
| 处理方法 | 根据缺失/异常类型选择合理方法 | 处理方法是否合理，是否先判断真实性 |
| 防数据泄露 | 只训练集fit，测试集transform | 是否有数据泄露，是否明确说明防泄露措施 |
| 特征工程 | 有业务意义的衍生特征 | 特征是否有业务意义，是否盲目构造 |
| 代码质量 | 完整可运行，分模块，有注释 | 代码是否可运行，是否分模块，是否固定随机种子 |
| 预处理流程图 | 强制输出，流程完整 | 是否输出流程图，流程是否完整清晰 |

**十四、本提示词整改能力（检测+自动整改）**

| 整改类型 | 可自动整改的内容 | 整改方式 |
| --- | --- | --- |
| P0致命 | 数据泄露(用全量数据fit)、异常值盲目删除、代码无法运行 | 修复数据泄露(只训练集fit)+保留真实异常+修复代码bug |
| P1重要 | 缺失值处理方法不当、特征工程不足、预处理流程图缺失 | 优化缺失值处理+补充业务衍生特征+生成预处理流程图 |
| P2优化 | 代码格式、注释、日志输出、数据格式 | 优化代码格式+补充注释+完善日志+统一数据格式 |
| 需手动 | 数据本身质量极差需要重新采集、模型完全不匹配需要更换 | 给出数据质量评估和模型更换建议，确认后执行 |

整改后输出：修改后的预处理代码_已整改.py + 预处理后数据_已整改.csv + HTML整改报告
