# 00_规则 · 全局方法论（本工作区的"宪法"）

> **这是什么**：**唯一真源**级的全局规则目录。这里规定"**怎么做才对**"——
> 硬约束、流程、验收红线、可视化规范、同步纪律。**8 份规则文件 ＋ 本索引**，全部可独立阅读。
>
> **性质**：**不随赛题变化**（与 `11_建模/`、`30_图表/` 等"实例层"相对）。
> **本目录的文件不得被赛题产出覆盖**；要改，只能改规则本身，并在文件内记变更。

## 二、最容易被违反的规则（**高频踩坑点**）

0. **计算授权门禁**（`工作约束.md` **§12**，**最高优先级**）：
   执行任何命令前先默答"**读还是算**"；属 **T2／T3** 的（正式求解、批量实验、参数扫描 ≥3 组、
   产出 `result*.xlsx` 或正式图表数据…）**必须先出申请单（§12.3 六栏）并获明确批准**；
   **"用户未回复"＝不批准**；"先跑个小的试试""顺便验证一下"**同样禁止**。
1. **同步方向**（`交付包同步与职责边界.md` §四 第 0 条）：
   口径级修改必须**真源 → 交付包**。只改交付包不回改真源 ＝ **反向偏移**，下次同步会把旧口径覆盖回来。
   自问：**"这条结论的真源在哪个文件？它改了没有？"**
   ⚠ **配套铁律（§〇 双工作区机制）**：**永不直接编辑交付工作区**（`…\2026国赛\Work_Space`）——
   一切改动只在**主工作区**，推送由 `tools/wsdiff.py` 执行（`apply` 默认 dry-run，`--yes` 需授权）。
2. **清单 ≠ 实际 也算漂移**（同文件 §四 第 5 条）：
   登记表声称某文件已入包而实际缺失，与"文件存在但未登记"**同等级别**，都撞官方第十一条红线。
   **每次登记后必须回验**（点数／哈希），**不得凭记忆登记**。
3. **模板永不被覆盖**（`工作约束.md` §6）：
   各目录 `00_*.md`／`00_模板.md` 是**模板**；实例从模板**复制**为 `<题号>_<名称>_<MMDD>.md`。

## 三、与本目录的关系约定

- **本目录文件不复制到子包**：`11_建模/00_*.md` 等包级执行要点**只链接本目录**，不重述规则（避免双份真源）。
- **冲突处理**：包级执行要点与本目录冲突时，**以本目录为准**并回询。
- **新增规则**：若某条经验需要成为"规则"（而非"记录"），写入本目录对应文件并在其变更记录登记；
  仅属过程留痕的，进 `99_过程与归档/`。

## 五、本目录维护规则（**改规则前必读**）

1. **节号冻结**：`工作约束.md` §6／§8／§11／§12（含 §12.x）、`建模作业规范.md` §5／§6、
   `建模求解流程总纲.md` §1.x／§7.x 等**已被全库引用**（`11_建模/`、`20_交付包/`、`40_复核/` 多处）——
   **重建或改写时不得改动其编号与标题**；确需调整，必须**同步全库引用**。
2. **变更必记**：任何规则修改必须在该文件末尾的**变更记录**表登记（版次 ＋ 改了什么）；
   **无变更记录 ≡ 未生效**。
3. **版本号规范**：规则文件形如 **`vN`（重大重建）／`vN.M`（条文增补）**。
4. **新增规则的归属**：跨包不变 → 本目录；包内执行细则 → 该包 `00_*.md`；纯过程留痕 → `99_过程与归档/`。
5. **与实例的边界**：本目录**只写"怎么做才对"**，**不写"本项目做到哪一步"**——
   项目现状一律放各包 `00_*.md` 的 §〇「当前状态与入口」。
