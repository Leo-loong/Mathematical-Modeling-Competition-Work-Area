# 交付包同步与职责边界（机制约定）

> **为什么立这一条**：本项目曾有 11 份成果文档**只存在于工作区、从未落进交付包**，
> 也曾出现"图表 CSV 有、规格卡无"（F-14）与"规格卡指向工作区路径、绘图者取不到数"两类漂移。
> 根因是**职责边界从未写明**。本文件把边界与同步动作固化，防止再次漂移。
>
> 依据：`00_规则/工作约束.md`（§6 工作区隔离、§11 独立完成与外部资料隔离）。

## 〇、双工作区机制（本项目的运行环境）

> **一句话**：**两个文件夹、一套真源、一条推送方向**。
> 新 Agent 只需记住：**"一切改动只改主工作区；交付工作区只读、由工具推送。"**

### 0.1 两个工作区

| | **主工作区**（真源） | **交付工作区**（对外） |
|---|---|---|
| 本机路径 | `C:\Users\wang-\Desktop\2026数学建模\Work_Space` | `C:\Users\wang-\Desktop\2026国赛\Work_Space` |
| 角色 | **全部工作**的发生地：审题／建模／求解／检验／交付包／复核／工具／归档 | 我方**对外交付内容**的落地处，经 **Syncthing 实时同步** |
| 谁在用 | 我方（建模 ＋ 复核 ＋ **内容写作**） | **排版成图方**在其上工作，并在其中产出**图表成品与 LaTeX 排版稿** |
| 是否真源 | ✅ **唯一真源** | ❌ **副本**（内容可能比真源旧，也可能含对方新增） |
| 可否直接编辑 | ✅ **一切改动都发生在这里** | ❌ **永不直接编辑**（见 0.4 第 1 条） |

> **路径可迁移**：两个根目录均声明在 `tools/wsdiff_rules.json`（`workspace_root`／`shared_root`），换机器只改这里。
> **对方产物**：`30_图表/最终图表/**`（绘图者已出的成品 PDF 与其 `.m` 脚本）——**只读、永不覆盖、永不计入删除**。

### 0.2 同步粒度：什么进、什么不进

**默认同步**：主工作区中「**除临时／垃圾文件外的全套**」（含 `11_建模/`、`40_复核/`、`20_交付包/`、`30_图表/`、`10_赛题/`、`00_规则/` 与根级文件）。
**为什么给全套**：对方发生冲突或资料缺失时，可回到**最原始的地方**自行取证 —— 故这些目录**不算违规，不要"清理"**。

**不外发（仅四类 ＋ 临时垃圾）**：

| 不外发 | 原因 |
|---|---|
| `tools/` | 我方工具与规则（含本机绝对路径） |
| `40_复核/03_变更报告/` | 我方变更报告／快照／增量包／推送留证 |
| `99_过程与归档/` | 内部留痕（旧版次、历史回执、旧日志留证） |
| `kb/` | **外部资料库**，按外部资料隔离律不进交付范围 |
| 临时与垃圾文件 | `_*`、`*.tmp`、`*.bak_sync`、`.DS_Store`、`__pycache__`… |

### 0.3 工具链（`tools/wsdiff.py`；规则 `tools/wsdiff_rules.json`）

| 命令 | 作用 |
|---|---|
| `python tools\wsdiff.py run` | **看差异**：生成 `40_复核/03_变更报告/A_变更明细_自动.md` ＋ `增量更新包/`（均不外发） |
| `python tools\wsdiff.py audit` | **体检**交付工作区（分类：合规／对方产物／不宜外发／垃圾；**只报告不修改**） |
| `python tools\wsdiff.py apply` | **预览**将写入的文件（dry-run，**不写**） |
| `python tools\wsdiff.py apply --yes` | **推送**（**须经用户明确授权**；覆盖前原件留证于 `推送留证/`，**不落交付工作区**） |
| `python tools\wsdiff.py snap --label X`、`snapdiff --a X --b Y` | 冻结快照 ／ 两快照对比（如"推送前 vs 推送后"） |
| `python tools\rebuild_index.py` | 重建 `工作区索引表.md`（统计 ＋ 逐项索引） |

### 0.4 五条纪律

1. **一切改动只在主工作区**；直接改交付工作区 ⟹ 会被下次同步覆盖，或产生**反向偏移**（见 §四 第 0 条）。
2. **推送是写操作**：`apply` 默认 dry-run；`--yes` **须经用户明确授权**；被覆盖的原件自动留证。
3. **对方产物永不覆盖、永不计入删除**（工具硬编码拒绝，`apply` 会明确报数）。
4. **判定以内容 md5 为准** —— Syncthing 会重写文件时间戳，**时间戳变化不算变更**。
5. **交付工作区不是真源**：若发现它比真源新（说明上轮漏改真源），**回填真源**后再走 §二。

### 0.5 交付工作区 —— **默认：Agent 主动忽略**（★用户裁定，最高优先）

> **★ 裁定**：交付工作区 **判定为「Agent 主动忽略」** —— **不再主动维护、不再主动比对、不再主动巡检**；
> **除用户明确要求"查看"或"推送"外，一律不予考虑**（**不读、不比、不报告、不主动提及**）。
>
> **理由（均为实测）**：
> ① 它是**对方的实时工作区**（Syncthing 周期同步），内容**随对方操作持续变化** ⟹ **任何主动结论都可能瞬间过期**
>    （实测：同一目录两次采样间隔数分钟，顶层文件构成即明显不同）；
> ② **用户将自行执行图表检查与迁移**；
> ③ 主动巡检消耗算力且易产出**误导性结论**（曾据瞬时快照误判"交付缺失"）。
>
> **仅两种情形允许访问**：**① 用户明确要求"查看／核对"；② 用户明确要求推送（`wsdiff apply --yes`）。**

**（以下仅在"用户明确要求"时适用）** 需要时如何读取交付工作区：

- **什么时候需要读**：① 确认推送是否生效；② 核对**对方新增／改动的成品**（`30_图表/最终图表/**`）；
  ③ 排查"对方反馈某文件不对"；④ 做推送前后对账（`snap` ＋ `snapdiff`）。
- **怎么读**：**只读** —— 直接用 `list_dir`／`read_file`／`search_content` 指向该目录即可（路径见 0.1）。
- **禁止**在其中：新建、修改、删除文件；运行脚本（会在对方副本里留下 `__pycache__` 等副产物）。
- **注意**：该目录是**对方正在工作的副本**，其内容**可能与主工作区不一致**（这正是差异工具的用途）；
  比对以 `md5` 为准；其内容**不得**当作真值引用（真值一律取主工作区的《A_数值口径总表》）。

## 一、职责边界（铁律）

| 区域 | 定位 | 内容性质 | 是否为"有效交付" |
|---|---|---|---|
| `11_建模/`、`30_图表/`、`40_复核/` | **过程与证据** | 推导、记录、检验日志、复核意见、工作地图 | ❌ **否**（仅作追溯） |
| `20_交付包/` | **可独立消费的素材** | 结论、数值、规格、可直接转写/出图的内容 | ✅ **是（唯一有效）** |
| **`50_论文/`** | **论文正文内容稿（我方产出）** | 各章节正文 **Markdown**（内容层；不含排版与图片） | ✅ **是（论文内容层交付物）** |
| `99_过程与归档/` | 归档 | 旧版、历史回执 | ❌ 否 |

> **`50_论文/` 的交付方向（本轮新增）**：**内容写作方（我方）→ 排版成图方（对方）**——
> 我方交付 **Markdown 章节稿**（含 `图X`／F 号占位、公式符号、引用标注位）；
> 对方据此**绘图＋LaTeX 排版**，产出图表成品与排版稿。**双方均不得改数**（真值仍是《A_数值口径总表》）。

**唯一判据**：

> **论文的某一节，写作者能否"只看交付包"就写出来？**
> **能 ⟹ 已落地；不能 ⟹ 未落地（无论工作区里写得多完整）。**

## 三、必须落地 vs 不必落地

| 必须落地（进 `20_交付包/`） | 不必落地（留在工作区） |
|---|---|
| 模型结论、推导链、假设、符号、数值口径 | 计划态文档（求解思路与工作流） |
| 检验记录与误差分析 | 收口确认、文档地图、成果清单 |
| 图表规格卡 ＋ 数据 CSV | 选题决策过程、审题过程稿 |
| 可运行源码与复现说明 | 复核意见原稿、差异台账原稿 |
| 支撑材料文件列表、AI 登记 | 归档区（`99_过程与归档/`） |
| 引用题录与术语表 | 复盘类内部读物（其**精华**须转写进交付包） |

**"精华转写"规则**：工作区中面向人阅读的复盘/评估类文档，
**不必整体搬迁，但其可被论文使用的结论必须转写进交付包**（如"一分钟读懂"、方法论要点）。

## 四、同步纪律（六条）

> **★ 第 0 条（真源优先，最高优先）**：同步的**方向**永远是 **真源（工作区）→ 交付包**。
> **禁止**直接修改交付包而不回改真源——那样会产生**反向偏移**：真源仍是旧口径，
> 下一次按 §二 同步时会把旧口径**覆盖回交付包**，且 `40_复核/` 与 `30_图表/` 也会各自朝不同方向漂移。
> **若发现交付包比真源新（说明上轮漏改了真源）**：以交付包内容为准**回填真源**，再走 §二 核对。
> **实操判据**：任何"口径级"修改完成后，自问"**这条结论的真源在哪个文件？它改了没有？**"
> 未改真源 ⟹ 视为**未完成**。



1. **交付包内不得出现指向工作区的路径引用**（规格卡的数据源必须指向本包 `04_图表包/data/`）；
   允许出现的例外**仅限三类**：①工作流程说明（如"回询台账登记处"），**含"溯源／复现指针"**
   （形如"来源：`11-3/Q4/code/q4_solver.py`；日志 `Q4/logs/…`"，用于第三方复现与我方追溯，
   **不属于取数路径**）；②AI 登记（过程记录，必须如实）；
   ③**运行日志原文**（`*.txt`／`*.log`）——属"**留证原文**"，其中的绝对路径是当时的**当前目录记录**而非取数路径，
   **改写会破坏与真源日志的逐字节一致**，反而损害可追溯性 ⟹ **按原文保留**，但须在
   `20_交付包/09_代码与复现/README_日志索引.md` 头部**统一声明**（2026-09-12 实测：14 份日志含此情况）。
   **可运行性例外**：运行辅助脚本（如 `rerun_chain.ps1`）**不得**硬编码绝对路径，须路径自适应。
2. **引用一律用交付包内相对路径**，保证写作者"不跳出本包即可完成写作与出图"。
3. **每次真源变更后逐项打勾**本表 §二；未同步项须在变更回复中**显式列出**。
4. **零外部本题引用**：交付包任何文件不得出现网络第三方（针对本题的）解法、数值、来源
   （依据 `00_规则/工作约束.md` §11）。
5. **"清单 ≠ 实际"同样算漂移**：登记表（如《A_支撑材料文件列表》）声称某文件已入包，而实际目录为**空或缺失**，
   与"文件存在但清单没有"**同等级别**，都会撞上官方第十一条"支撑材料与论文不符"的红线。
   **每次登记后必须回验**（`Get-ChildItem` 点数、哈希比对），**不得凭记忆登记**。
