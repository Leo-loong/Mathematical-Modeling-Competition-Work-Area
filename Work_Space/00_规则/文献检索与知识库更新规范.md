# 文献检索与知识库更新规范

> 背景：网络检索文献与本地知识库已合并统一检索。比赛期 Agent 搜网络资料后，
> 按"下载成功转 md / 失败写摘要 md"两种形态存入 `kb\source`，并运行一键更新脚本。
> 引擎版本 1.3：`kb\engine\update.py`（一键增量）、`p5_search.py`（检索）。

---

## 1. 收录流程（比赛期 SOP）

```
网络检索 → ① 可下载：下载并转高质量 md → 存 kb\source
        → ② 不可下载：Agent 自编摘要 md      → 存 kb\source
        → ③ PDF/DOC 原件可同放（引擎按文件名级注册 kind=doc）
        → ④ python kb\engine\update.py（精修→元数据→重建索引→刷新 MOC）
        → ⑤ 引用登记（写进论文的文献 → 20_交付包/07_引用与术语 题录表）
```

- 存放位置：`kb\source` 下**任意新文件夹或散文件均可**（引擎动态发现，无需登记），
  比赛期建议统一 `kb\source\比赛文献\`（或按题目建子目录 `kb\source\比赛文献\<题号>\`）。
- **更新时机**：每次新增内容后必须运行 `update.py`；其输出新增/移除清单落盘 `data\update_log.txt`。

## 2. 文件质量要求

### 2.1 下载成功 → 转 md
- 转换质量参照 `kb\文档批量转Markdown_踩坑与经验固化.md`（可运行脚本在 `kb\source\temp\`）
- 文件头部必须写元信息块：

```
> 来源：<URL 或出处>
> 检索日期：<YYYY-MM-DD>
> 检索式：<使用的搜索词>
> 可信度：官方/学术期刊/权威机构/公众号等（自评）
```

### 2.2 下载失败 → Agent 自编摘要 md
- 命名建议：`摘要_<主题>_<来源域名/日期>.md`
- 内容至少含：题名、出处与 URL、检索日期、核心内容摘要（模型/方法/结论要点）、
  可用于本题何处、未能获取全文的原因
- 摘要头部同样写 §2.1 元信息块，并加一行 `> 形态：摘要（未获取全文）`

### 2.3 通用约束
- 不改动 `kb\source` 中已有文件；新内容一律新增
- 引擎会自动做重复折叠（与库内相同内容只显示一条），无需人工去重
- 引用数字/公式前注意 `[疑OCR(繁体混入)]` 标签提示（回原件核对）
- **不外发**：`kb/` 属**外部资料库**，**不参与对外同步**（同步范围见 `00_规则/交付包同步与职责边界.md` **§〇**）；
  kb 内容亦**不得**进入 `20_交付包/`（唯一例外：AI 登记中如实记载"曾检索联网"这一**事实**，见《工作约束》§11.4）

## 3. 引用闭环

1. 检索→收录→按《建模求解流程总纲》对应阶段使用（题型路线/模型改进/参数依据）
2. 写进论文的每一条文献：登记 `20_交付包/07_引用与术语/` 题录表（含正文引用处标注位置）
3. 交付前对照官方红线：参考文献规范列出 + **正文引用处标注齐全**（角色分工与交付验收 K 类）

## 4. 快速命令

```powershell
# 新增文献后（推荐，一键）：
python kb\engine\update.py

# 检索（常规 / 深挖 / JSON）：
python kb\engine\p5_search.py 查询词
python kb\engine\p5_search.py 查询词 --deep
python kb\engine\p5_search.py 查询词 --json
```
