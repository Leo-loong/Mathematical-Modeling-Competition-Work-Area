# 角色分工与交付验收清单

> 交接前，建模者必须逐项自查本清单；**未全绿不得进入 20_交付包**。
> 写作者接收时按此清单复核，缺项直接回询，不做"自行补齐"。

## 一、分工铁律（一句话版）

> **★ 职责边界变更（本轮）**：原"写作者"一职**拆分为两方**——
> ① **内容写作方（我方，主工作区）**：负责论文**各章节正文内容**，交付 **Markdown**；
> ② **排版成图方（对方，交付工作区）**：负责**图表绘制**与 **LaTeX 排版／格式合规**。

| 角色 | 归属 | 对什么负全责 | 交付形态 |
|---|---|---|---|
| **建模者** | 主工作区 | 论文的**内容要素权威**——假设、符号、数值口径、图表设计（规格卡＋数据）、误差边界 | `20_交付包/` 素材 |
| **内容写作方** | **主工作区（我方）** | 论文**各章节正文**（问题重述／问题分析／假设／符号／建模／求解／结果分析／检验／评价／参考文献引用）的**内容与表述** | **`50_论文/` 下的 Markdown 章节稿** |
| **排版成图方** | 交付工作区（对方） | **图表绘制**（按规格卡＋CSV）与 **LaTeX 排版**（页数／编号／匿名／公式字体等**格式合规**） | 图表成品 PDF ＋ 排版 PDF |

- **三条不变量**：① 数值一律取《A_数值口径总表》，**任何一方不得改数**；② 图表数据只认 `04_图表包/data/*.csv`，其**语义与标签由规格卡冻结**；③ **内容与排版分离**——我方**不接管 LaTeX／绘图**，对方**不改内容**（需改内容须回询）。
- 排版成图方**不需要读懂建模过程**；建模者**不干预表达风格**；内容写作方**不干预排版细节**。

## 二、交付验收清单

### A. 模型叙述（01）

- [ ] 编号公式完整，每个公式在正文中被引用或解释
- [ ] 推导可独立阅读（不依赖 11_建模 过程文档）
- [ ] 伪代码与代码文件一一对应（文件路径标注）
- [ ] 术语与《术语对照表》一致

### B. 符号表（02）

- [ ] 五列齐全：符号 / 含义 / 单位 / 首次出现 / 备注
- [ ] 按"论文分组"重组（几何量/物理量/统计量…），非按推导序
- [ ] 附 **LaTeX 表格代码**（可直接粘入论文编译）
- [ ] 每个符号的取值/来源已注明（实测/拟合/文献）
- [ ] 全文符号与符号表一一对应（无表外符号）

### C. 假设清单（03）

- [ ] 每条假设含四栏：内容 / 合理性或必要性论证 / 简化代价 / 后续处理去向
- [ ] 条数 3–8 条，无与模型无关的多余假设
- [ ] 附 **LaTeX 版本**
- [ ] 与"模型评价"节的升级叙事有前后呼应标注

### D. 图表包（04）★ 本次重构重点

- [ ] `04-0_图表总规划.md`：全表一览（编号/类型/归属/目的/状态）；**经验基准 12–20 张**
      （本项目实例 **50 张**；正文最终呈现由 `20_交付包/13_论文可删减部分/` 裁剪，正文 ≤30 页）
- [ ] 每图一卡（**规格卡七要素＋2 新增必填，缺一不可**；**权威定义见 `30_图表/02_图表规格卡/00_模板.md`**）：图号图名 / 目的（评委看什么）/ 图类型与选择理由 /
      数据源（CSV 路径＋列说明）/ 坐标轴·单位·范围 / 配色与尺寸（引用设计语言实例）/ 绘制注意点（易错处）
- [ ] 每卡含**设计语言引用**（色板/线型/尺寸/字号）与（如需）本图特例
- [ ] `data/*.csv` 就绪：列名有说明；含全量档 `_full`；与数值口径总表一致
- [ ] `figures_reference/` 参考图就绪（可复核结构）
- [ ] 图类型多样化：非图表类（流程图/示意图/机理图）≥ 3 张
- [ ] 每图有明确"展示目的"，无凑数图
- [ ] 表格类素材给出三线表数据与表头设计

### E. 数值口径总表（05）

- [ ] 唯一真值源；每个数字：值 / 口径名 / 来源 / 容差
- [ ] 已知的多口径数字全部登记并说明差异
- [ ] 易错点（因子、单位、正负号、区间 vs 对称误差）显式标注

### F. 可靠性与方法学（06）

- [ ] 可靠性分析全文 + 验证记录（含失败实验与决策依据）
- [ ] 实验决策链完整（为什么走这条路、放弃过什么）

### G. 引用与术语（07）

- [ ] 参考文献题录规范（作者/年份/期刊/DOI 可验证）
- [ ] 术语对照表（口语 ↔ 学术）

### H. 章节素材映射（08）

- [ ] 论文每一节都有：素材指针 + 必写要点 + 建议篇幅
- [ ] 预留位明确标注（摘要/问题重述/格式页 = 写作者全权）

### J. 问题分析与摘要/评价要点（01-0、10）

- [ ] `01-0_问题分析与拆解.md`：问题本质、子问题拆解表（输入/输出/方法/关系）、
      技术路线、框架图登记齐全——支撑论文"问题分析"节（★★★★☆）
- [ ] `摘要要点卡.md`：每小问的**具体数字结果**齐全（写作者成文时不得增删数字）；
      检验数字与口径总表一致
- [ ] `模型评价与改进.md`：优点对应机制证据；局限对应来源假设；
      改进方向具体到做法
- [ ] 三者与知识库论文标准结构（11 模块）逐一对应，无缺失模块

### I. 代码与复现（09）★ 官方红线（违反可能取消评奖资格）

- [ ] 论文附录含**全部完整、可运行**的源程序代码（官方第五条：缺失源程序、
      程序不能运行、运行结果与论文不符 → 可能取消评奖资格；**不做裁剪**）
- [ ] 入口脚本唯一明确；依赖与版本说明
- [ ] 复现指南可让第三方一键复算论文中**每一个**关键数字
- [ ] 求解结果与论文正文数字逐项一致（对照《数值口径总表》）
- [ ] **支撑材料包**（官方第十一条）：可运行源程序 + 自主查阅的数据资料 +
      较大篇幅中间结果图表，RAR/ZIP **≤20MB**
- [ ] 支撑材料**文件列表**已放入论文附录
- [ ] 支撑材料与论文内容相符（不符可能取消资格）
- [ ] 支撑材料中无身份/学校/赛区信息

### K. 官方格式合规（红线，源自《论文格式规范》2026 修订稿）

- [ ] 页面结构：P1 承诺书 / P2 编号专用页 / P3 摘要专用页（≤1 页，页码从此页起）
- [ ] 正文：自 P4 起，**无目录**、**≤30 页**
- [ ] **匿名**：摘要页、正文、附录、支撑材料中任何地方无身份/学校/赛区信息
- [ ] 电子版：单独文件 PDF/Word ≤20MB，**第一页为摘要专用页**（不放承诺书/编号页）
- [ ] 参考文献：规范列出 + **正文引用处标注**齐全
- [ ] 有程序却未在附录说明、或无支撑材料未注明"本论文没有用到程序/支撑材料"

### L. AI 使用合规（红线，依官方《人工智能工具使用规定》2026 试行）

- [ ] 论文参考文献之前设"AI 工具使用声明"（二选一固定句式，未使用/使用了）
- [ ] 使用 AI 的：支撑材料含"**AI 工具使用详情.pdf**"（官方四要素齐全：
      工具版本/目的环节/关键交互/采纳与人工核验）
- [ ] 核心建模与分析内容经过**逐项人工审查核实**（有核验记录，非 AI 直出）
- [ ] 无隐瞒/虚假声明（申报的用途与实际一致）
- [ ] 模板：`20_交付包/12_AI工具使用详情/00_模板.md`

### M. 论文正文（`50_论文/`，我方内容稿）★ 本轮新增

> 适用对象：**内容写作方的产出**（Markdown 章节稿）。**排版与成图不在本类范围**（由排版成图方负责）。

- [ ] 每节正文**只引用**《A_数值口径总表》的数字，**逐项对表**；无手抄、无自算
- [ ] 每节标注其**素材来源**（`20_交付包/` 的哪个文件），可追溯
- [ ] 正文**不出现内部代号**（检验编号／口径编号／工作区台账编号；见 `建模作业规范.md` §6）
- [ ] 术语全文一致（按 `07_引用与术语/A_题录表.md` §五 的统一定名）
- [ ] 图表**只以 `图X`／`表X` 占位并给出 F 号**（成品由排版成图方插入；正文不内嵌图片）
- [ ] 公式**给出编号占位与符号**，与《A_符号表》一一对应
- [ ] 摘要：四要素齐全、每问 ≥1–2 个对比性数字（**素材见 `10_摘要与结论要点/摘要要点卡.md`**）
- [ ] 不改动任何**建模结论**；发现素材缺口 → 按 §三 回询，**不自行补齐**

## 三、回询规则

- 素材缺项/数值疑问/模型细节：**登记到 `40_复核/02_差异台账/A_复核差异台账.md`**（问题闭环台账，
  闭环需复核方确认）→ 用户转达建模组；建模组的批量变更以 `40_复核/03_变更报告/A_变更明细_自动.md`
  **＋ 同目录 `增量更新包/`** 回传（机制见 `00_规则/交付包同步与职责边界.md` **§〇**）
- **内容写作方与排版成图方均不得**自行推测物理机制、**不得**修改任何数值与公式
- 建模组回复后更新交付包并在变更记录登记版本号

## 四、版本纪律

- 交付包内所有文件带版本号（v1.0 起）；变更必须写变更记录
- 数值变更 = 硬变更：全队知悉，所有受影响图表重出（**变更影响面**由 `tools/wsdiff.py run` 自动列出）
- **变更通道（双工作区）**：一切改动**只改主工作区**；推送由 `tools/wsdiff.py` 执行
  （`apply` 默认 dry-run，`--yes` 需授权），**禁止**直接编辑交付工作区
- **规则文件版本号**：`00_规则/` 内文件形如 **`vN`（重大重建）／`vN.M`（条文增补）**，
  且必须在文件末尾**变更记录**表登记（未登记 ≡ 未生效）
- **变更报告三件套**：增量明细（`A_变更明细_自动.md`）＋ 增量包（`增量更新包/`）＋ 快照
  （`wsdiff.py snap`／`snapdiff`）—— 目的：对方**照单覆盖、无需自查**
