## 1. 删除操作（硬性约束）

- **任何删除操作最多允许尝试 3 次**。
- 3 次尝试仍失败（例如被环境安全机制 `SAFE_DELETE_BULK_GUARD` 拦截、文件被占用、
  权限不足等）时：
  1. **立即停止重试**，不得换方式继续尝试；
  2. 将待删除项记录到 `kb\source\temp\待手动删除清单.txt`（路径 + 原因 + 文件数）；
  3. 在**任务结束时**统一告知用户，由用户手动删除。
- 删除优先用「移动到隔离目录」代替物理删除（可恢复、不触发批量删除保护）；
  只有用户明确要求删除时才执行物理删除，并遵守上述 3 次限制。

## 2. 不打扰用户

- 后台任务必须无窗口：Python 用 `pythonw.exe` + `CREATE_NO_WINDOW(0x08000000)`；
  调用外部控制台程序（`tar.exe` 等）同样必须加 `CREATE_NO_WINDOW`。
- 禁止反复弹出并关闭 cmd 窗口。合并多步为单脚本一次执行，减少命令条数。

## 3. 内容保真优先

- 文档转换必须保证内容一字不差，逐段校验必须 0 丢失。
- 拿不到的信息（如 OCR 坐标）不硬凑，改为降级方案并明确标注。
- 错误结构比无结构更糟：表格重建等高风险操作需高置信门槻。

## 4. 组件安装

- 优先使用系统自带能力（Windows OCR、Word COM、tar.exe），装依赖是最后选项。
- 确需安装时，须说明用途与体积，并在用完后告知用户可卸载。

## 12. 计算任务分级授权（★最高优先级门禁 · 用户指令）

> **本条为最高优先级**：与其他条款或既有习惯冲突时，**以本条为准**。
> **执行任何命令前，先过 §12.6 的自检三问。**

### 12.0 立法缘由（如实留痕，以事实为鉴）

**2026-09-11 · 越权事实**：用户请求为"**再次检索并学习知识库教材，并评估现在是否可以正式开启第二问求解**"。
该请求性质是**评估**（属 T0 只读分析），其合规产出边界应为"**结论文档 ＋ 执行申请单**"。
但实际执行中，**未经任何批准**即完成了：Q2 **全时程正式求解（10800 步）**、**8 套检验实验**（W2／E2／E4／E6／E7 等）、
**6 张参考图渲染**、以及**多份交付包文档落地**。
⟹ 越权规模：**T3 级**（远超"冒烟"许可范围）。

用户裁定：**"这次就算了"**——即**不予追究**，但**明确要求**"编写极强的约束，专门杜绝未经许可就大规模求解的毛病"。
**本事实登记在案，不得作为先例。**

### 12.1 分级定义（量化；**任一**命中即属该级）

| 级别 | 界定 | 授权方式 |
|---|---|---|
| **T0 只读分析** | 不运行任何求解／仿真代码。仅：读文件、检索、统计、**静态**检查代码、写文档 | **自主执行** |
| **T1 冒烟自检** | 同时满足：时程 ≤ 60 s **且** 步数 ≤ 2 000 **且** 节点 ≤ 41 **且** 单次耗时 ≤ 20 s **且** **不产出任何交付物** | **自主执行**，但须：①脚本与日志标注 `SMOKE`；②结果**仅用于验证"能否跑通"**，**不得**作为任何结论、图表或口径的依据 |
| **T2 小规模验证** | 时程 ≤ 600 s **或** 步数 ≤ 20 000 **或** 单次耗时 ≤ 300 s **或** 产出中间数据文件 | **须先申请** |
| **T3 正式求解／批量实验** | 时程 > 600 s **或** 步数 > 20 000 **或** 参数扫描 ≥ 3 组 **或** 批量运行 ≥ 5 次 **或** 产出 `result*.xlsx`／正式图表数据 **或** 累计算力 > 10 min | **须书面申请 ＋ 明确批准** |

**跨级不降级**：一批相关任务按其中**最高**级别定性。
**严禁**通过拆分（如把 T3 拆成数次 T2）规避申请。

### 12.2 禁止行为（逐条；违者按 §12.5 处置）

1. 以"**先跑起来看看**""试试能否跑通""顺便验证一下"为由启动 T2／T3；
2. 把 T3 任务**拆成多个 T2** 逐次规避申请；
3. 在**未获批准**时以后台方式启动；
4. 把"**用户未回复**"当作默许——**沉默一律视为不批准**；
5. 以上下文长度、token 预算、任务可能被中断等**任何理由**抢先执行；
6. 在"**检索／学习／评估／复述／核对／检查**"类请求中**夹带执行**；
7. 收到"**是否可以／能否／要不要开始 X**"式提问时，产出**超出**"结论 ＋ 申请单"的范围；
8. 以"**小规模验证**"为名，实际执行 T2／T3 规模的算例。

### 12.3 申请单（T2／T3 必填；**缺任一栏即无效**）

| # | 栏目 | 要求 |
|---|---|---|
| 1 | **目的与产出物** | 回答什么问题、产出什么文件（**写明路径**） |
| 2 | **规模与数值设置** | 时程／步数／网格／内部子步／参数组数／运行次数 |
| 3 | **实测计时依据** | **必须先有 T1 冒烟实测**，据此外推总耗时；**不得凭空估算** |
| 4 | **所属阶段** | 对应《建模求解流程总纲》阶段①–⑦；**上一阶段是否已验收** |
| 5 | **失败预案** | 不收敛／超时／结果异常时的处置 |
| 6 | **本次不做的事** | 明确边界，防止范围蔓延 |

### 12.4 批准的有效期与范围

- 批准**仅对本次申请单描述的规模与范围有效**；规模扩大（即使仍是 T2）**须重新申请**；
- 批准**不得跨阶段复用**、**不得跨问复用**。

### 12.5 违规处置（发现或发生后**立即**执行）

1. **立即终止**相关进程；
2. 越权产出**一律不得采信**：不得写入 `20_交付包/`、不得回填《A_数值口径总表》；
3. 若已误写入交付包，须在该文件标注"**（未经授权产出，待复核）**"并报告；
4. 在 **AI 登记**中如实留痕（规模、时长、已产出物清单、整改措施）；
5. 主动向用户报告，**请示是否废弃或重做**；
6. **自我报告义务**：越权后**必须主动报告**；隐瞒不报按**严重违规**处理。

### 12.6 每次执行命令前的自检三问（**动作前默答，任一条不确定即停手**）

1. 这条命令是"**读**"还是"**算**"？
2. 若为"算"，属 **T0／T1／T2／T3** 哪一级？
3. 若是 T2／T3——**本轮是否有针对该规模与范围的明确批准**？

**任一条不确定 ⟹ 停手，先出申请单。** 不得"先跑了再说"。

### 12.7 阶段门（不得跨阶段推进）

- 依《建模求解流程总纲》：①审题 → ②选型 → ③假设与符号 → ④建模 → ⑤求解 → ⑥检验 → ⑦评价；
- **每完成一个阶段，必须向用户报告并获批准**后方可进入下一阶段；
- ★**"评估／可行性判断"类请求的合规产出边界 ＝ 结论文档 ＋ T2／T3 申请单**，**绝不含执行**；
- **阶段⑤（求解）进入条件**：①③④已完成并验收；②本阶段 T2／T3 **申请单已获明确批准**。

### 12.8 技术闸门（脚本层强制）

1. 所有求解类脚本**默认只"声明规模"**：启动后打印时程／步数／网格／**预计耗时**，随即**退出**；
2. 必须**显式传入** `--go`（或环境变量 `ALLOW_RUN=1`）**且**声明规模不超过批准值，才真正执行；
3. 脚本首行输出须打印 `[SCALE]` 声明行，便于事后审计；
4. **现状（2026-09-12 实测复核）**：**闸门已实装**——Q1–Q4 的求解主脚本均"默认只声明规模并退出，
   须 `--go` 才真正执行"，并打印 `[SCALE]` 声明行。
   取证示例：`11_建模/11-3_算法与管线/Q4/code/q4_solver.py`（打印 `[SCALE] …` 后
   `if '--go' not in sys.argv: … sys.exit(0)`）；各问 `logs/` 中的 `[SCALE]` 行即为**事后审计留痕**。
   **仍按人工把关的部分**：检验／诊断／绘图类小脚本未必装闸门 ⟹ **一切启动仍按 §12.1 分级由人工严格把关**
   —— 闸门只是兜底，**批准才是前提**，不得因"有闸门"而放松。

### 12.9 与既有条款的关系

- 本条**不改变** §1–§11 的任何要求，只**增加**一道计算授权闸门；
